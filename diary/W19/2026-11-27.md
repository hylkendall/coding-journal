### 1. 冷启动第 1 题：点号后面跟着参数名

题目：传进文物编号和属性名，返回这件文物的这个属性值。两行各打印什么？`return` 那行怎么改？

```javascript
const collection = {
  101: { title: "Mask", year: 1920 },
  102: { title: "Vase", year: 1850 }
};

function getInfo(id, prop) {
  return collection[id].prop;
}

console.log(getInfo(101, "title"));
console.log(getInfo(102, "year"));
```

我答的：`"Mask"`、`1850`
结果：两行都是 `undefined`

**错在哪**：`collection[id]` 写对了。`.prop` 只会照字面去找一个名字就叫 `"prop"` 的属性，跟参数 `prop` 没关系。文物对象里只有 `title` 和 `year`，所以得到 `undefined`。这周第三次碰到这个点了（周三 `records.id`、昨天 `.key`、今天 `.prop`）。

正确写法：

```javascript
return collection[id][prop];
```

**判断办法**：看这个名字有没有出现在 `function getInfo(id, prop)` 的括号里。出现了就是变量，用方括号。

**实验**：故意给文物加了一个名字就叫 `prop` 的属性，三种写法放在一起跑：

```javascript
const collection = {
  101: { title: "Mask", year: 1920, prop: "我就是名叫 prop 的属性" }
};

function getInfo(id, prop) {
  console.log(collection[id].prop);     // 我就是名叫 prop 的属性
  console.log(collection[id]["prop"]);  // 我就是名叫 prop 的属性
  console.log(collection[id][prop]);    // Mask
}

getInfo(101, "title");
```

### 2. 问题：实验代码连着跑了几次都报错，不知道错在哪

答：代码本身没问题，是 Safari 控制台还记着上一次粘贴的 `const collection`。只要页面不刷新，第二次粘贴就成了"同一个名字声明两次"，报 `SyntaxError`，整段代码一行都不跑。办法是每次粘贴前先按 ⌘R 刷新页面。

看红字：冒号前面是报错类型，冒号后面说的是哪个名字或哪个值出了问题，红字右边还会显示行号。

### 3. 冷启动第 2 题：`&&` 两边的顺序

题目：给某件文物加一个标签。文物不存在就什么都不做，标签已经有了也不重复加。运行后会发生什么？

```javascript
const collection = {
  101: { title: "Mask", tags: ["gold"] }
};

function addTag(id, tag) {
  const item = collection[id];
  if (!item.tags.includes(tag) && item) {
    item.tags.push(tag);
  }
}

addTag(101, "royal");
addTag(999, "royal");
console.log(collection[101].tags);
```

我答的：`["gold", "royal"]`。实际跑了一下，报错，说是 tags 的问题。
结果：跑到 `addTag(999, "royal")` 时报 `TypeError`，Safari 里显示 `undefined is not an object (evaluating 'item.tags')`。程序在这里停下，最后的 `console.log` 没执行，什么也没打印。

**错在哪**：`collection[999]` 不存在，所以 `item` 是 `undefined`。`&&` 从左往右算，左边一上来就读 `item.tags`，等于读 `undefined` 的属性，于是报错。右边的 `&& item` 本来就是防这个错的，可它写在后面，还没轮到就已经报错了。

正确写法：

```javascript
if (item && !item.tags.includes(tag)) {
```

改完以后打印 `["gold", "royal"]`。**防报错的判断要写在 `&&` 最左边。**

---

### 4. 我的改法：用 `?.`

我写的：

```javascript
if (!item?.tags.includes(tag) && item) {
```

结果：能跑，打印 `["gold", "royal"]`，不报错。

为什么不报错：`item` 是 `undefined` 时，`?.` 直接停下，后面的 `.tags.includes(tag)` 整串都跳过，结果是 `undefined`。`!undefined` 是 `true`，所以接着算右边的 `item`，它不成立，就不进 `if`。

点评：这版防了两次，`?.` 防读 `.tags` 时报错，`&& item` 防 `push` 时报错。两个都不能少，删掉 `&& item`，999 会在 `push` 那里报 `TypeError`。还是推荐 `item && ...`：只判断一次，读起来就跟题目要求一样，"文物存在，并且还没有这个标签"。

### 5. 复习页问题：`Object.hasOwn` 说的"非继承"，还有为什么更可靠

问题：这个"非继承"什么意思？为什么它更安全、更可靠？

答：
1. "非继承"超纲了，现在跳过。等到第 21 个模块"类和 this 关键字"再学。
2. 为什么比 `if (obj.prop)` 可靠，看成绩单这个例子：

```javascript
const scores = { tom: 0, amy: 90 };

if (scores.tom) { ... }            // 不进去：0 被当成"没有"
Object.hasOwn(scores, "tom")       // true：名单上有 Tom
```

`if (obj.prop)` 看的是值，值是 `0`、`false`、`null`、`undefined`、`""` 都会被当成没有。`Object.hasOwn` 只看属性在不在。

**钩子**：对象还能用一些不是自己写的属性，这叫继承来的，比如 `toString`。`in` 会把这些也算上，`Object.hasOwn` 不算。等模块 21 再学。

### 6. 问题：`hasOwnProperty()` 为啥不能用

答：能用，普通对象上它跟 `Object.hasOwn` 的结果完全一样，复习页和测验里都会出现。推荐 `Object.hasOwn` 只是因为有一种很少见的情况：对象里刚好有个属性也叫 `hasOwnProperty`，调用时就会报 `TypeError`。

判断属性在不在，有三种写法，都是对的，属性名都要加引号：

```javascript
Object.hasOwn(car, "year")   // 推荐
car.hasOwnProperty("year")   // 老写法
"year" in car
```

### 今天的规律

这周错的地方几乎都是两类。第一类是"这个名字到底指什么"：变量写到了点号后面，或者属性名前面少写了 `对象.`。第二类是 `&&`、`||` 两边谁先算。函数怎么拆、分支怎么走，你每次都写对了。测验四选一能过，冷启动老是错，是因为冷启动要你在脑子里把代码准确跑一遍，而且专门挑你错过的地方出。
