**一、变量 vs 属性（冷启动）**
1. 读一个不存在的**属性**，得到 `undefined`；读一个从没声明过的**变量**，报 `ReferenceError`。
2. 前面有 `对象.` 就是去对象里找属性（`album.artist`），没有就是找变量（`artist`）。
3. 解构 `const { artist: singer } = album` 只造出变量 `singer`，`artist` 不是变量。

**二、JSON 是文字**
1. JSON 指的是那段文字。在 JS 里拿到的 JSON 是字符串，`.json` 文件也是纯文本文件。
2. `JSON.parse` 不会改原来的字符串，而是照着文字另造一个新值交出来，要用变量接住。跟 `toUpperCase()` 一样。
3. 字符串上取属性得到 `undefined`：`data.album`。要取值得用 `parse` 之后的 `obj`。
4. 文字写的是什么，`parse` 出来就是什么：`'{"a": 1}'` 是对象，`'[1, 2]'` 是数组，`'42'` 是数字，`'true'` 是布尔值。`stringify` 交出来的永远是字符串。
5. `parse` 完得到的是普通 JS 对象，就不叫 JSON 了。代码里直接写的 `{ name: "Ann" }` 也不是 JSON。
6. 为什么要 `parse`：服务器传过来的数据只能是文字，转成对象才能用点号取值。

**三、问答游戏：函数之间用变量交接**
1. 随机取一项：`arr[Math.floor(Math.random() * arr.length)]`。
2. `getRandomQuestion` 要返回整个对象，不能只返回 `.question`，后面还要用这道题的 `choices` 和 `answer`。
3. 每调用一次随机函数，就是重新抽一次。**一个结果要用两次以上，必须先存进变量。**
4. 交接套路：`const a = 函数1(...)` → `const b = 函数2(a.属性)` → `函数3(a, b)`。变量就是函数之间交接的地方。
5. 判断类的函数（裁判）只用参数，不调用别的函数。题目里的 "takes X as the first parameter" 已经说了传什么、接什么，先照着写好第一行。
6. 写函数时发现里面出现了别的函数调用，停下来问：这个结果是不是应该从参数进来？
7. 调用的代码统一放在所有函数下面，这几行就是整个程序的总流程。
8. 参数和外面的变量同名时，函数里用的是参数，也就是调用时传进来的那个。
9. 判断答案要用 `===`。字符串的 `includes` 查的是"包含"，`"Hamburger".includes("Ham")` 是 `true`。

**四、唱片收藏：读写对象**
1. 数据有两层：外层的键是 `id`（专辑编号），值是专辑对象；专辑里的键才是 `prop`（`albumTitle`、`artist`、`tracks`）。中文版把 album 译成了"相册"，应该是"专辑"。
2. 点号后面写的是字面上的属性名。`records.id` 找的是名叫 `"id"` 的属性，得到 `undefined`。属性名装在变量里时要用方括号：`records[id][prop]`。
3. `.tracks` 和 `["tracks"]` 一样；`[tracks]` 不加引号，会被当成变量，报 `ReferenceError`。
4. 数字键只能用方括号：`records.5439` 是 `SyntaxError`。
5. 判断对象有没有某个属性用 `Object.hasOwn(obj, "tracks")`。`includes` 只有数组和字符串有，对象调用会报 `TypeError`。
6. 方括号前面紧挨着一个名字，是取值（`arr[0]`）；前面什么都没有，是造新数组（`[value]`）。
7. `if` / `else` 后面要跟花括号 `{ }`，写成圆括号整个文件报 `SyntaxError`，一行都跑不起来。
8. `return records` 放在所有分支结束之后，函数最后返回一次。放进某个分支里，走其他分支时返回的就是 `undefined`。
9. 前面分支已经排除掉的情况，后面不用再判断：`value !== ""` 可以删，最后一个 `else if` 可以直接写 `else`。
10. 对象操作四件套：改或加 `obj[k] = v`；删 `delete obj[k]`；查 `Object.hasOwn(obj, k)`；数组追加，有就 `push`，没有就 `= [v]`。
