### 1. 冷启动第 1 题：点号后面跟变量名

```javascript
const shelf = {
  7: { name: "Vase", tags: ["clay"] }
};
const id = 7;
const key = "name";

shelf[id].key                   // a
shelf[id][key]                  // b
shelf[id]["key"]                // c
shelf[id].tags.includes("clay") // d
```

我答的：a `"Vase"`，b `"Vase"`，c `undefined`，d 语法错误
正确答案：a **`undefined`**，b `"Vase"`，c `undefined`，d **`true`**

**a 错在哪**：以为 `.key` 会读变量 `key`。其实 `.key` 就等于 `["key"]`，找的是名叫 `"key"` 的属性，跟 c 是同一句话。点号后面写什么，就找什么。只有不加引号的 `[key]`（也就是 b）才会去读变量。

**d 错在哪**：这种一长串的，要从左往右一段一段拆，每拆一段就问一句"现在手里是什么"：`shelf[id]` 是对象，`.tags` 是数组 `["clay"]`，在数组上调用 `.includes("clay")`，结果是 `true`。
另外，就算真的在对象上调用 `includes`，报的也是 `TypeError`，不是语法错误。语法错误是代码根本读不通，整个文件一行都不跑，比如 `records.5439`。

### 2. 冷启动第 2 题：抽一道题，再从这道题的选项里抽一个

题目里已经给了 `pickRandom(arr)`（从数组里随机拿一项）和 `judge(question, choice)`，要写出主流程。

我写的：

```javascript
const question = pikeRandom(questions);
const choice = question.choices[Math.floor(Math.random() * choices.length)];
console.log(judge(question, choice));
```

结果：第 1 行、第 2 行都会报 `ReferenceError`。

**错在哪**：
- 第 1 行 `pikeRandom` 拼错了，JS 会把它当成另一个从没声明过的名字。
- 第 2 行 `choices.length`：`choices` 不是变量，它是 `question` 的属性。前面没写 `question.`，JS 就去找一个叫 `choices` 的变量，找不到就报错。
- 第 2 行也没必要把随机公式重写一遍，`pickRandom` 什么数组都能接。

正确写法：

```javascript
const question = pickRandom(questions);
const choice = pickRandom(question.choices);
console.log(judge(question, choice));
```

### 4. 第 9 步：addTag，文物存在、而且还没有这个标签时，才加进去

我写的：

```javascript
function addTag(id, tag) {
  const artifact = collection[id];
  if (!artifact[tags].includes(tag)) {
    artifact[tags].push(tag);
  }
}
```

提示：调用 addTag 并传入一个新标签时，应将该标签添加到文物的 tags 数组中。（这句我没看懂）

**提示的意思**：测试调用了一次 `addTag(101, 新标签)`，再去查 `tags` 数组，发现新标签没加进去。没加进去，是因为函数一跑就报错了。控制台里没看到报错，是因为我只定义了函数、还没调用它，测试一调用才报错。

**错在哪**：
- `artifact[tags]`：方括号里没加引号，`tags` 会被当成变量。没有这个变量，所以报 `ReferenceError`。`tags` 是固定的属性名，应该用点号。
- 少了一个判断：题目原话是"如果文物**存在**且……"，我只写了后半句。`id` 不存在的时候，`artifact` 是 `undefined`，再去读 `undefined.tags` 就报 `TypeError`。

正确写法：

```javascript
if (artifact && !artifact.tags.includes(tag)) {
  artifact.tags.push(tag);
}
```

**记住**：`artifact` 一定要写在 `&&` 的左边。`&&` 左边不成立，就不会再去算右边，这样 `.tags` 就不会被读到。
`artifact.tags` 本身是数组，所以在它上面用 `includes` 没问题。

### 5. 第 11 步：moveArtifact，往 locations 里推一个新位置

我写的：

```javascript
collection[id][locations].push({ gallery, year });
```

提示：调用 moveArtifact 应该将一个新的 { gallery, year } 对象推入文物的 locations 数组。

**错在哪**：跟第 9 步是同一个问题，`[locations]` 被当成了变量，报 `ReferenceError`。应该写 `collection[id].locations.push(...)`。

**检查办法**：写完方括号，看里面的名字在函数第一行的括号里能不能找到。

这个研讨会里，放进方括号的只有 `id`。

**这步写对的地方**：先写了 `if (collection[id])` 判断文物存不存在；`{ gallery, year }` 用了简写，等于 `{ gallery: gallery, year: year }`。

### 6. 第 19 步：buildSummary，用模板字符串返回 5 行简介

我写的：

```javascript
return `${artifact.title}
"Category: " ${artifact.category}
"Curator: " ${artifact.Curator.name}
"Current Gallery: " ${currentLocation}
"On Display: " ${artifact.onDisplay}`
```

提示：buildSummary(101) 应该包含文物的标题，Golden Mask。（其实标题本身没写错）

**错在哪**：
- `artifact.Curator`：C 写成了大写。属性名是小写的 `curator`，大小写不同就是另一个名字，所以读到 `undefined`，再读 `.name` 就报 `TypeError`。函数在这一行就停了，什么都没返回，所以测试连第 1 条"包含标题"都没过。

```javascript
return `${artifact.title}

```

**写对的地方**：第 2 行起都顶格写。反引号里的空格会原样保留，缩进了，每行前面就会多出空格。同样的道理，注释写进反引号里，也会变成输出的文字。

### 7. 我问的：`[object Object]` 到底是什么

问题：已经第二次看到它了，一个小写一个大写，是不管写什么都显示这个，还是一种格式模板？

答：
- 它是一段固定的文字。任何普通对象被转成文字，都是这同一串，跟对象里装了什么无关。小写 `object` 是大类，跟 `typeof` 得到的 `"object"` 是同一个词；大写 `Object` 是具体种类，普通对象就叫这个名字。
- 什么时候会出现：把整个对象放进 `${ }` 里，或者用 `+` 和字符串拼在一起。
- 看到它，就回去找少写的那个 `.属性名`。
- 想看对象里装了什么，直接用 `console.log(obj)`，别包在反引号里；或者用 `JSON.stringify(obj)`。
- 数组不一样：数组转成文字，是把每一项用逗号连起来，`["a", "b"]` 会变成 `a,b`。
