## 一、CSS 动画是什么、怎么工作

CSS 动画由两块拼起来：

1. **`@keyframes 名字 { … }`**：写"剧本"，规定各个时间点元素长什么样。可以用 `from`/`to`（就是 0%/100%），也可以用百分比加中间帧（0%、50%、100%……）。
2. **元素上的 `animation-*` 属性**：决定播哪个剧本、怎么播。这里写的名字必须和 `@keyframes` 的名字一模一样，对不上就不播。

和 `transition` 的区别有两点。第一，transition 只有起点和终点两个状态，必须有状态变化（比如 `:hover`）才会触发。第二，animation 可以有任意多个中间帧，页面一加载就能自己播，还能循环。

| 属性 | 管什么 | 默认值 |
|---|---|---|
| `animation-name` | 播哪个 `@keyframes` | `none` |
| `animation-duration` | 一轮多长 | 相当于 `0s`，不写就等于不播 |
| `animation-timing-function` | 速度曲线（`ease` / `linear` / `ease-in-out`…） | `ease` |
| `animation-delay` | 开始前等多久 | `0s` |
| `animation-iteration-count` | 播几轮，`infinite` 是无限 | `1` |
| `animation-direction` | `normal` / `reverse` / `alternate`（来回）/ `alternate-reverse` | `normal` |
| `animation-fill-mode` | 播放前后元素保持什么样子：`none` / `forwards`（停在最后一帧）/ `backwards` / `both` | `none` |
| `animation-play-state` | `running` / `paused` | `running` |

默认值的出处：MDN 上每个属性页面底部的"形式定义"里有一行"初始值"，你可以自己点开核对。

**简写**：`animation: spin 2s linear 1s infinite;`。里面出现两个时间值时，**第一个是 duration，第二个是 delay**。

**性能**：优先给 `transform` 和 `opacity` 做动画，浏览器处理它们不需要重新算布局。动 `width`、`left`、`margin` 这类属性，每一帧都要重排，容易卡。

## 二、动画的无障碍问题和 `prefers-reduced-motion`

动画会给这几类人带来问题：

- **前庭障碍**：大幅位移、旋转、缩放、视差滚动会让人头晕恶心，原理和晕车一样。
- **光敏性癫痫**：快速闪烁可能诱发发作。WCAG 成功标准 2.3.1 规定一秒内闪烁不超过 3 次。
- **注意力或认知障碍**：一直在动的东西会抢注意力，让人读不下去内容。
- **停不下来的动画**：WCAG 2.2.2 要求，自动播放超过 5 秒的移动内容必须能暂停、停止或隐藏。

**`prefers-reduced-motion`** 是一个媒体特性，读取的是用户在操作系统里的设置。在 Mac 上的位置是：系统设置 → 辅助功能 → 显示 → 减弱动态效果。它只有两个值：`no-preference`（没开）和 `reduce`（开了）。

浏览器**不会**自动替你停掉动画，规则得你自己写。常见有两种写法。

写法 A：默认有动画，在 `reduce` 里关掉或减弱。

```css
.box { animation: spin 2s infinite; }
@media (prefers-reduced-motion: reduce) {
  .box { animation: none; }
}
```

写法 B：默认没有动画，只在 `no-preference` 里加上。这种更稳，不支持这个特性的环境默认就是安全的。

```css
@media (prefers-reduced-motion: no-preference) {
  .box { animation: spin 2s infinite; }
}
```

另外，**减弱不等于删光**。要去掉的是大幅位移、旋转、缩放；淡入淡出这种不涉及移动的效果，一般可以保留。

**卡 1**

正面：

```css
:root { --size: 20px; }
p { color: var(--size, red); }
```
Will the text of `p` be red? Why?
`p` 的文字会是红色吗？为什么？

背面：
No. `--size` is defined, so the fallback is not used. `var()` substitutes `20px` → `color: 20px` is invalid → the declaration behaves like `unset` → `color` is inherited from the parent.
The fallback depends on whether the variable is defined, not on whether its value is valid for the property.

不会。`--size` 有定义，所以不用 fallback。`var()` 替换后得到 `color: 20px`，这个值无效，于是这条声明按 `unset` 处理，`color` 从父元素继承。
fallback 看的是变量有没有定义，不看它的值对这个属性是否有效。

标签：`CSS::Variables`

**卡 2**

正面：

```css
@keyframes move {
  from { transform: translateX(0); }
  to   { transform: translateX(200px); }
}
.ball { animation: move 1s; }
```
When the animation ends, where is `.ball`? How do you make it stay at the end?
动画结束后，`.ball` 在哪儿？怎样让它停在终点？

背面：
Back at its starting position: it jumps back to its own styles, because `animation-fill-mode` defaults to `none` (keyframe styles apply only while the animation runs).
Add `forwards`: `animation: move 1s forwards;` → it keeps the styles of the last frame it played.

回到起点：它会跳回元素自己的样式，因为 `animation-fill-mode` 默认是 `none`（keyframes 的样式只在播放期间生效）。
加上 `forwards`：`animation: move 1s forwards;`，它就会保持播放结束时那一帧的样式。

标签：`CSS::Animation`

**卡 3**

正面：

```css
.orbit {
  transform: translate(-50%, -50%);
  animation: spin 5s linear infinite;
}
@keyframes spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}
```
While the animation is playing, does `translate(-50%, -50%)` still apply?
动画播放期间，`translate(-50%, -50%)` 还生效吗？

背面：
No. During playback, the keyframes' `transform` replaces the element's own `transform` entirely; the two are not combined. To keep the translate, you must write it into the `transform` of every keyframe yourself.

不生效。播放期间，keyframes 里的 `transform` 会把元素自己的 `transform` 整个替换掉，两者不会合并。想保留这个平移，就得自己把它写进每一帧的 `transform` 里。

标签：`CSS::Animation`

**卡 5**

正面：
In fCC's Moon Orbit lab, the `.orbit` box itself swings around (visible if you give it a border). Why does the moon still trace a circle centered on the earth?
fCC 的月球轨道 lab 里，`.orbit` 盒子本身在甩大圈（给它加边框就能看到）。为什么月亮仍然绕着地球画出一个圆？

背面：
`.orbit` is an invisible arm, not the drawn orbit line. `translate(-50%, -50%)` pins its bottom-right corner at the earth's center. That point is also the rotation center: `transform-origin` defaults to the center of `.orbit`'s untransformed box, and since `.orbit` (no top/left) exactly overlaps `.space`, that center is `.space`'s center, which is the earth's center. The moon, at the arm's other end (top-center), circles that point.

`.orbit` 是一根看不见的摇臂，不是画出来的轨道线。`translate(-50%, -50%)` 把它的右下角钉在地球中心。这个点同时也是旋转中心：`transform-origin` 默认是 `.orbit` 未变换时的盒子中心；而 `.orbit` 没写 top/left，正好和 `.space` 重合，所以这个中心就是 `.space` 的中心，也就是地球中心。月亮挂在摇臂的另一头（顶部正中），绕着这个点画圆。

标签：`CSS::Transform`
