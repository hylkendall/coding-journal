企鹅收工，今天的任务完成了。整只企鹅一张图片都没用，全是长方形 div 加上圆角、渐变、定位、叠放和变形拼出来的。下面按"骨架 → 造型 → 动作"拆开讲，最后说几处可以改进的地方。

**一、骨架**

背景层是天空、两座山、太阳和地面，都用绝对定位，前后顺序靠 z-index 排：后山 1、左山 2、地面 3、企鹅 4。

企鹅层的思路是"一个相对定位的盒子，里面贴满绝对定位的贴纸"：

- `.penguin` 写了 `position: relative`，尺寸固定 300×300，所有零件都以它为坐标原点。水平居中靠 `margin: auto`。`margin-top` 写在 `margin` 后面，所以能盖掉简写里的上边距。
- `.penguin * { position: absolute; }` 一行就让里面所有后代脱离文档流。注意 `*` 选不中伪元素，所以 `.penguin-body::before` 要自己再写一遍 `position: absolute`。
- 零件的尺寸和位置几乎都用 %，相对的是各自的父零件。眼睛、嘴放在 head 里，手和脚放在 body 里，嵌套关系决定了谁跟着谁走。

**二、造型**

1. **用 border-radius 捏形状**：50% 得到圆或椭圆，四个值得到蛋形。手臂的 `30% 30% 30% 120%` 比较特别：同一条边上两个角的半径加起来超过 100% 时，浏览器会把四个角按同一个比例一起缩小，结果是左下角一大段弧、其余角收得较尖，就成了翅膀的样子。
2. **同色遮盖当橡皮擦**：眼睛本身是黑椭圆，里面的 eye-lid 是一个更大的白椭圆，颜色和脸一样，盖住眼睛的下半截，剩下那道弯弧就是眯眼笑。
3. **用遮挡造山**：左山是正方形用 `skew` 斜切成平行四边形，后山是正方形转 45° 变成菱形。两座山的下半截都被地面挡住，露出来的部分就是山坡和山尖。太阳是同一个手法：一个圆推出右上角一大半，只露出一角。地面没写 `top`。绝对定位元素不写偏移时，会停在它原本在文档流里的位置，也就是企鹅下面，再用 `margin-top: -58px` 往上提一点，刚好托住企鹅的脚。
4. **用 z-index: -1 把手脚塞到身体后面**：手脚是 body 的孩子，正常会画在 body 上面，设成 -1 后就退到了后面。为什么能退到 body 后面、却不会退到地面后面，这涉及"层叠上下文"，计划里没有单独安排。先记个钩子，以后遇到 z-index 不听话时再讲。
5. **用伪元素补零件**：肚子上的灰斑是 `::before` 做的，写了 `content: ""` 它才会出现，不用多写 HTML。
6. **用渐变做光影**：头和身体用 45deg 渐变，左下暗、右上亮，看起来有体积。身体的渐变还给色标写了位置（0%、25%、67%），用来控制明暗过渡的快慢。颜色统一放在三个变量里，改一处，全身跟着变。

**三、动作**

1. `transform-origin: top left` 让左臂绕肩膀转。不写的话默认绕中心转，会像风车一样。
2. wave 只写了 10% 到 40% 这几帧。0% 和 100% 用元素自己的 `rotate(130deg) scaleX(-1)` 补上。40% 到 100% 起止值一样，所以每 3 秒里，前 1.2 秒挥两下，后 1.8 秒不动。省掉的那些帧本身就做出了停顿。
3. `:active` 配合 `transition`：按住时放大 1.5 倍，松手后缩回。`transition` 写在 `.penguin` 本身上，所以放大和缩回两个方向都有过渡。如果只写在 `:active` 里，按下时会慢慢变大，松手时会一下子弹回去。

**四、一个藏起来的现象：衬衫上的字为什么断成两行**

"I CSS" 显示成了 "I" 和 "CSS" 两行，代码里并没有写换行。原因是 `.shirt` 的孩子全是绝对定位，它自己没有内容撑开，宽度是 0。p 以 `.shirt` 为包含块，能用的宽度也是 0，只能按最窄的方式排，遇到空格就断行。这正是你学定位时挂的那个钩子："absolute 不写宽度，会收缩到内容大小"。一分钟验证：给 `.shirt` 加上 `width: 200px`，"I CSS" 会合成一行，爱心会压到字上。

**五、可以改进的地方**

1. **单位不统一**：零件都用 %，只有衬衫用 px。把 `.penguin` 改成 150×150，身体会整体缩小，衬衫却留在原地，字也不会变小。
2. **没写 `prefers-reduced-motion`**：挥手动画是 infinite 的。按周一学的内容，系统里开了"减弱动态效果"，它也照样挥。做作品集 lab 时可以把这一条练上。
3. **地面用了 `100vw`**：100vw 会把竖向滚动条的宽度也算进去，所以页面有滚动条时，地面会比页面宽一截，撑出横向滚动条。这里没出问题，是因为 body 上有 `overflow: hidden` 兜着。第 5 步加那一行，多半就是为了兜住太阳和地面伸出去的部分。
4. **小事**：`transition` 里的 `0ms` 本来就是默认值，可以省掉。

## 卡壳的点:

**先说第 6 点：同比例缩小是怎么算的**

规则分三步：

1. 对每一条边，把挨着这条边的两个角在这个方向上的半径加起来。
2. 用边长除以这个和，每条边得到一个比值。
3. 取四个比值里最小的那个，记作 f。只要 f 小于 1，四个角的所有半径都乘以 f。

关键在于：不是只把超标的那个角削掉，而是四个角一起按同一个比例缩小，一直缩到最挤的那条边刚好放得下。打个比方，合影太宽装不进相框时，你不会只把最胖的那个人裁掉，而是把整张照片等比例缩小。

拿企鹅的手臂 `30% 30% 30% 120%` 算一下：

- 底边：左下 120% 加右下 30%，等于 150%，比值是 100/150 = 2/3。
- 左边：左上 30% 加左下 120%，也是 150%，比值同样是 2/3。
- 顶边和右边：都是 30% 加 30%，等于 60%，比值大于 1，不用缩。

所以 f = 2/3，四个角都乘以 2/3，实际效果等于 `20% 20% 20% 80%`。

规则的出处是 W3C 的 CSS Backgrounds and Borders 规范里 "Overlapping Curves" 那一节。一分钟验证：在开发者工具里把手臂的 border-radius 改成 `20% 20% 20% 80%`，形状完全不变；再改成 `30% 30% 30% 70%`，也就是只削掉超标的那个角，你会发现另外三个角变圆了，形状就不一样了。

**卡 1**

正面：
A `@keyframes` rule has no `0%` (`from`) and no `100%` (`to`) keyframe. Where do the start and end values of each cycle come from?
一个 `@keyframes` 既没有写 `0%`（`from`），也没有写 `100%`（`to`）。每一轮动画的起点值和终点值从哪里来？

背面：
From the element's own value of that property (what it would be without the animation). So if the last written keyframe equals the element's own value, the element stays still from that keyframe until 100% — a built-in pause.
来自元素自身的该属性值，也就是不播动画时它本来的值。所以，如果最后一个写出来的关键帧和元素自身的值相同，那么从这一帧到 100% 元素是静止的，等于自带一段停顿。

标签：`CSS::Animation`

**卡 2**

正面：
In `transform: scaleX(n)`, what do `n = 2`, `n = 0.5`, and `n = -1` each do?
在 `transform: scaleX(n)` 里，`n = 2`、`n = 0.5`、`n = -1` 分别产生什么效果？

背面：
`n` is the horizontal scale factor. `2`: twice as wide. `0.5`: half as wide. `-1`: same width, mirrored left-to-right. A negative factor flips the element; its absolute value sets the size.
`n` 是水平方向的缩放比例。`2`：宽度变为两倍。`0.5`：宽度变为一半。`-1`：宽度不变，左右镜像翻转。比例为负数时元素会翻转，比例的绝对值决定大小。

标签：`CSS::Transform`

正面：
By default, around which point do `rotate()` and `scale()` act on an element? How do you make an element rotate around its top-left corner instead (e.g. an arm swinging at the shoulder)?
默认情况下，`rotate()` 和 `scale()` 以元素的哪个点为中心起作用？想让元素绕左上角旋转（比如手臂绕肩膀摆动），要怎么写？

背面：
Default: the element's center (`transform-origin` initial value is `50% 50%`). To pivot at the top-left corner: `transform-origin: top left;`
默认以元素中心为中心（`transform-origin` 的初始值是 `50% 50%`）。想绕左上角转，写 `transform-origin: top left;`。

**卡 4**

正面：
`.penguin:active { transform: scale(1.5); }`
Case A: `transition: transform 1s;` is on `.penguin`.
Case B: the same `transition` is only on `.penguin:active`.
What happens on mouse press and on mouse release in each case?
`.penguin:active { transform: scale(1.5); }`
情况 A：`transition: transform 1s;` 写在 `.penguin` 上。
情况 B：同样的 `transition` 只写在 `.penguin:active` 里。
两种情况下，按下鼠标和松开鼠标时分别会怎样？

背面：
A: both press (grow) and release (shrink back) are animated.
B: press is animated; release snaps back instantly.
Reason: a change uses the `transition` of the state being entered. In B, the base state being returned to has no `transition`.
A：按下时放大、松开时缩回，两个方向都有过渡。
B：按下时有过渡；松开时瞬间弹回。
原因：状态切换时，用的是"切换后那个状态"上写的 `transition`。B 里松开后回到的基础状态没有写 `transition`。

标签：`CSS::Transition`

**卡 5**

正面：
`.shirt` is absolutely positioned with no width set. All its children, including a `<p>` containing "I CSS", are also absolutely positioned. Why does "I CSS" wrap onto two lines?
`.shirt` 是绝对定位，没有设置宽度。它的所有子元素也都是绝对定位，其中包括一个内容为 "I CSS" 的 `<p>`。为什么 "I CSS" 会断成两行？

背面：
All of `.shirt`'s children are out of the normal flow, so nothing gives it width, and its width is 0. The `<p>` uses `.shirt` as its containing block and has no width of its own, so its available width is also 0. It shrinks to its narrowest possible width and breaks at every possible line-break point (here, the space). Giving `.shirt` an explicit width puts "I CSS" back on one line.
`.shirt` 的子元素全部脱离了文档流，没有东西撑开它，所以它的宽度是 0。`<p>` 以 `.shirt` 为包含块，自己也没有设宽度，所以它可用的宽度也是 0，只能收缩到最窄，在每一个可以断行的地方断开（这里就是那个空格）。给 `.shirt` 设一个明确的宽度，"I CSS" 就会回到一行。

标签：`CSS::Positioning`

**卡 6**

正面：
`border-radius: 30% 30% 30% 120%;` — along the bottom edge, the two corners' horizontal radii add up to 150% of the width. How does the browser resolve this?
`border-radius: 30% 30% 30% 120%;`：沿着底边，两个角的水平半径加起来是宽度的 150%。浏览器怎么处理？

背面：
For each edge, compute edge length ÷ (sum of the two radii along that edge). Take the smallest ratio, f. If f < 1, multiply every radius of all four corners by f — not just the oversized corner. Here f = 100/150 = 2/3, so the result equals `20% 20% 20% 80%`.
对每条边，计算"边长 ÷ 挨着这条边的两个半径之和"，取其中最小的比值 f。如果 f < 1，四个角的所有半径都乘以 f，而不是只削减超标的那个角。这里 f = 100/150 = 2/3，结果等于 `20% 20% 20% 80%`。

标签：`CSS::BorderRadius`

**卡 7**

正面：
Hook: an arm is a child of `.penguin-body` and has `z-index: -1`. It is drawn behind its parent `.penguin-body`, yet still in front of the ground (`z-index: 3`). What concept explains this?
钩子：手臂是 `.penguin-body` 的子元素，设了 `z-index: -1`。它被画在父元素 `.penguin-body` 的后面，却仍然在地面（`z-index: 3`）的前面。这背后是什么概念？

背面：
Stacking context. `.penguin` (`position: relative; z-index: 4`) creates one; `.penguin-body` (`z-index: auto`) does not. So `z-index: -1` moves the arm to the bottom of `.penguin`'s stack: behind the body, but never outside `.penguin`. To be studied later.
层叠上下文。`.penguin`（`position: relative; z-index: 4`）会创建一个层叠上下文，`.penguin-body`（`z-index: auto`）不会。所以 `z-index: -1` 只是把手臂移到 `.penguin` 这一层的最底部：在身体后面，但永远出不了 `.penguin`。以后再学。

标签：`CSS::Hook`
