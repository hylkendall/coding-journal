### 数字和常用数字方法（理论）

**1. isNaN**
NaN 是 number 类型里一个特定的值，表示"算坏了"（比如 `0 / 0`），所以 `typeof NaN` 是 `"number"`。它连自己都不等于，没法用 `===` 判断。全局 `isNaN(x)` 先做一步 `+x` 再看结果是不是 NaN，实际问的是"这东西能当数字用吗"；`Number.isNaN(x)` 不转换，只认 NaN 这个值本身。今天最难的一点：NaN 是一个值的**名字**，不是"凡是不是数字"的描述（叫"不是猫"的狗），所以 `Number.isNaN("blabla")` 是 `false`。写代码检查计算有没有算坏，用 `Number.isNaN`。`Number.NaN` 就是 NaN，认识就够。

**2. parseFloat() 和 parseInt()**
都从字符串开头往后读，读到不能用的字符就停，把读到的部分变成数字；开头就不行返回 `NaN`；开头空格忽略，开头正负号保留。`parseFloat` 停在不能构成小数的字符（第二个小数点也算），`parseInt` 停在第一个非数字字符，小数点也算，所以它是砍掉小数，不是四舍五入。跟一元 `+` 的区别：`+` 要整个字符串都合法，`+"42px"` 是 `NaN`，`parseInt("42px")` 是 `42`。

**3. toFixed()**
四舍五入到指定位数，返回**字符串**，不传参数默认 0 位。`console.log` 打印字符串不带引号，所以测验那题选 `5.7` 被判错是题目措辞的坑（英文原题也写 "output"），它考的是类型。返回字符串是为了显示，`"7.00"` 末尾的 0 只有字符串留得住。整数直接调用要包括号：`(7).toFixed(2)`。

**插曲：复习页的 `--num` / `num--`**
"旧值"是这一行执行前的值，不是最开始的 5。你自己总结得对：写在 `console.log()` 里的 `num--` 真的会改 `num`，跟 `console.log(num - 1)` 只打印不改是两回事。

正面：
Why does `7.toFixed(2)` throw a `SyntaxError`? How do you fix it?
┄┄┄┄┄┄┄┄
`7.toFixed(2)` 为什么会报 `SyntaxError`？怎么改？

背面：
JavaScript reads the dot right after the integer `7` as a decimal point, so `toFixed` is not treated as a method call. Wrap the number in parentheses: `(7).toFixed(2)` gives `"7.00"`. Calling it on a variable, such as `num.toFixed(2)`, needs no parentheses.
┄┄┄┄┄┄┄┄
JavaScript 把紧跟在整数 `7` 后面的点当成小数点，所以 `toFixed` 不会被当作方法调用。把数字包在括号里：`(7).toFixed(2)` 得到 `"7.00"`。在变量上调用，比如 `num.toFixed(2)`，不需要括号。
