### 理解比较和条件语句（理论）

**1. null 和 undefined 的比较**
`undefined` 是声明了还没赋值（也是函数没传参数时的默认值），`null` 是故意设成"没有值"。它俩在比较里走两套规矩：比大小（`<` `>` `<=` `>=`）先把两边转成数字，`null` 变 `0`，`undefined` 变 `NaN`；`==` 碰到 `null` / `undefined` 不转数字，它俩只跟彼此相等（和自己相等）。所以 `null >= 0` 是 `true`，`null == 0` 却是 `false`；`undefined` 比大小全是 `false`；`undefined == NaN` 两道关都过不去，是 `false`。
记一句：**比大小先转数字；`==` 碰到 null / undefined 只认彼此。** 比方是"量身高"和"认亲"。实际写代码一律用 `===`，这些坑主要是测验考。

**2. switch 和 if/else**
`switch` 拿一个值跟一串 `case` 比，用的是 `===`，不做类型转换，所以 `"2"` 匹配不上 `case 2`。匹配上就执行，碰到 `break` 跳出；没写 `break` 会接着执行下面 case 的代码，不再检查 case 的值，直到碰到 `break` 或 switch 结束，这叫 fall-through。都没匹配上就走 `default`。一个变量对多个固定值用 `switch`；范围、多个变量、`&&` `||` 组合条件用 `if / else`。

**卡 6**
正面：
What does this code print? Why?
```javascript
let fruit = "apple";
switch (fruit) {
  case "apple":
    console.log("苹果");
  case "banana":
    console.log("香蕉");
    break;
  case "cherry":
    console.log("樱桃");
}
```
┄┄┄┄┄┄┄┄
这段代码打印什么？为什么？

背面：
`苹果`, then `香蕉`. `case "apple"` matches, but it has no `break`, so execution continues into the next case's code without checking that case's value. It stops at the first `break` or at the end of the `switch`. This is called fall-through.
┄┄┄┄┄┄┄┄
先打印 `苹果`，再打印 `香蕉`。`case "apple"` 匹配上了，但它没有 `break`，所以接着执行下一个 case 的代码，而且不再检查那个 case 的值，直到碰到第一个 `break` 或者 switch 结束才停。这叫 fall-through（贯穿）。

标签：`js::conditionals`

**卡 8（钩子卡）**
正面：
What does this code print?
```javascript
const a = 2;
if (1 == "1") {
  let b = 3;
  console.log(a + b);
}
console.log(b);
```
┄┄┄┄┄┄┄┄
这段代码打印什么？

背面：
`5`, then `ReferenceError: b is not defined`. A variable declared with `let` or `const` inside a pair of curly braces `{}` exists only inside those braces (block scope), so `b` is gone after the `}`. `a` is declared outside, so it can be used inside. Code runs from top to bottom, so `5` is printed before the error. Block scope is taught formally in Module 3.
┄┄┄┄┄┄┄┄
先打印 `5`，再报 `ReferenceError: b is not defined`。用 `let` 或 `const` 在一对花括号 `{}` 里声明的变量，只在这对花括号里面存在（块级作用域），所以出了 `}` 之后 `b` 就没了。`a` 声明在外面，所以里面能用。代码从上往下执行，所以报错之前 `5` 已经打印出来了。块级作用域在模块 3 正式学。

标签：`js::scope js::errors`

**卡 9**
正面：
A file starts with `console.log("hi");` and later has both `let a = 1;` and `let a = 2;` at the same level. What happens when you run it? Why doesn't `hi` appear?
┄┄┄┄┄┄┄┄
一个文件第一行是 `console.log("hi");`，后面在同一层里既有 `let a = 1;` 又有 `let a = 2;`。运行它会怎样？为什么 `hi` 没有打印出来？

背面：
Nothing is printed; you only get `SyntaxError: Identifier 'a' has already been declared`. JavaScript checks the syntax of the whole file before running any of it, so a SyntaxError stops everything, even the lines above it. A ReferenceError is different: it happens only when that line runs, so earlier output has already been printed.
┄┄┄┄┄┄┄┄
什么都不打印，只报 `SyntaxError: Identifier 'a' has already been declared`。JavaScript 在运行之前会先检查整个文件的语法，所以一旦有 SyntaxError，整个文件一行都不执行，连它上面的行也不执行。ReferenceError 不一样：它是运行到那一行才发生的，所以前面的输出已经打印出来了。

标签：`js::errors`
