**卡 1**
正面：
Are `" "`, `"0"` and `"false"` truthy or falsy? How do you tell whether a string is truthy?
┄┄┄┄┄┄┄┄
`" "`、`"0"`、`"false"` 是 truthy 还是 falsy？怎么判断一个字符串是不是 truthy？

背面：
All three are truthy. The only falsy string is the empty string `""`. A string is truthy as long as it contains at least one character (its `length` is greater than 0), no matter what that character is: a space, `"0"` and `"false"` all count.
┄┄┄┄┄┄┄┄
三个都是 truthy。唯一是 falsy 的字符串是空字符串 `""`。只要字符串里至少有一个字符（`length` 大于 0），它就是 truthy，不管那个字符是什么：空格、`"0"`、`"false"` 都算。

标签：`js::booleans`

**卡 2**
正面：
What do `Number("3.9kg")`, `Number(" 3.9 ")` and `parseFloat("3.9kg")` return? How is `Number()` different from `parseFloat()`?
┄┄┄┄┄┄┄┄
`Number("3.9kg")`、`Number(" 3.9 ")`、`parseFloat("3.9kg")` 分别返回什么？`Number()` 跟 `parseFloat()` 有什么不同？

背面：
`NaN`, `3.9` and `3.9`. `Number()` checks the whole string: spaces at the start and end are ignored, but if anything other than the number is mixed in, the result is `NaN`. It follows the same rule as unary `+`. `parseFloat()` reads from the start, stops at the first character it cannot use, and returns the part it has read.
┄┄┄┄┄┄┄┄
`NaN`、`3.9`、`3.9`。`Number()` 检查整个字符串：首尾的空格会被忽略，但只要混进了数字以外的东西，结果就是 `NaN`。它跟一元 `+` 是同一条规则。`parseFloat()` 从开头往后读，遇到第一个用不了的字符就停下，把读到的部分返回。

标签：`js::numbers js::type-coercion`

**卡 3**
正面：
Which of these exist: `Math.floor()`, `Number.floor()`, `Number.isNaN()`, `Math.isNaN()`? How do you decide between `Math.` and `Number.`?
┄┄┄┄┄┄┄┄
`Math.floor()`、`Number.floor()`、`Number.isNaN()`、`Math.isNaN()` 里哪些存在？怎么区分什么时候用 `Math.`、什么时候用 `Number.`？

背面：
Only `Math.floor()` and `Number.isNaN()`. Of the ones learned so far, `Math` methods calculate: they take numbers and produce a new number (`floor`, `ceil`, `round`, `trunc`, `random`, `max`, `min`, `abs`, `pow`, `sqrt`). `Number` tools check whether something is a number or convert to a number (`Number.isNaN(x)`, `Number("3.9")`). Rule: to calculate, use `Math`; to check or convert, use `Number`. Two other kinds have no `Math.` or `Number.` in front: `toFixed()` is called on the number itself, as in `(9.999).toFixed(2)`, and `parseInt()`, `parseFloat()` and `isNaN()` can be called with no prefix.
┄┄┄┄┄┄┄┄
只有 `Math.floor()` 和 `Number.isNaN()`。在目前学过的里面，`Math` 的方法负责计算：拿数字算出一个新数字（`floor`、`ceil`、`round`、`trunc`、`random`、`max`、`min`、`abs`、`pow`、`sqrt`）。`Number` 的工具负责判断是不是数字、或者转成数字（`Number.isNaN(x)`、`Number("3.9")`）。口诀：要计算用 `Math`；要判断或转换用 `Number`。另外两类前面既不加 `Math.` 也不加 `Number.`：`toFixed()` 是在数字本身上调用，比如 `(9.999).toFixed(2)`；`parseInt()`、`parseFloat()`、`isNaN()` 可以不加前缀直接调用。

标签：`js::numbers`

**卡 4**
正面：
What does this code print? When should `toFixed()` be called in a calculation?
```javascript
const price = (19.5).toFixed(2);
console.log(price + 5);
console.log(price - 5);
```
┄┄┄┄┄┄┄┄
这段代码打印什么？在一串计算里，`toFixed()` 应该在什么时候调用？

背面：
`19.505`, then `14.5`. `toFixed()` returns a string, `"19.50"`. `+` with a string on one side concatenates. `-` can only do math, so it converts `"19.50"` to the number `19.5` and subtracts. Rule: keep calculating with numbers, and call `toFixed()` only at the moment you print.
┄┄┄┄┄┄┄┄
先打印 `19.505`，再打印 `14.5`。`toFixed()` 返回的是字符串 `"19.50"`。`+` 有一边是字符串就做拼接；`-` 只能做数学，所以先把 `"19.50"` 转成数字 `19.5` 再减。规则：计算时一直用数字，只在打印的那一刻才调用 `toFixed()`。

标签：`js::numbers js::type-coercion`

**卡 5**
正面：
For which values is `x == null` `true`? With `const sugar = 0;`, what do `sugar == null ? 5 : sugar`, `sugar ?? 5` and `sugar || 5` give?
┄┄┄┄┄┄┄┄
`x == null` 在 `x` 是哪些值时为 `true`？在 `const sugar = 0;` 的情况下，`sugar == null ? 5 : sugar`、`sugar ?? 5`、`sugar || 5` 分别得到什么？

背面：
Only `null` and `undefined`. The results are `0`, `0` and `5`. `0 == null` is `false`, so the ternary hands over `sugar`, which is `0`. `??` also falls back only for `null` / `undefined`, so it keeps `0`. `||` falls back for every falsy value, and `0` is falsy, so it gives `5`. `x == null` is a common, deliberate use of `==`: it checks "null or undefined" in one go.
┄┄┄┄┄┄┄┄
只有 `null` 和 `undefined`。结果分别是 `0`、`0`、`5`。`0 == null` 是 `false`，所以三元运算符交出 `sugar`，也就是 `0`。`??` 同样只在 `null` / `undefined` 时才用默认值，所以保留 `0`。`||` 碰到任何 falsy 值都用默认值，`0` 是 falsy，所以得到 `5`。`x == null` 是一种常见的、有意使用 `==` 的写法：一次检查"是 null 或 undefined"。

标签：`js::operators`

**卡 6**
正面：
What is redundant in `n = isBad ? n = 1 : n = 2;`, and how should it be written?
┄┄┄┄┄┄┄┄
`n = isBad ? n = 1 : n = 2;` 里哪里是多余的？应该怎么写？

背面：
The two `n =` inside the ternary. The ternary operator itself hands over a value (`1` or `2`), so assign it once, outside: `n = isBad ? 1 : 2;`. The longer version still works, but it assigns `n` twice.
┄┄┄┄┄┄┄┄
三元运算符里面那两个 `n =`。三元运算符本身就会交出一个值（`1` 或 `2`），所以在外面赋值一次就够：`n = isBad ? 1 : 2;`。长的写法也能跑，但会给 `n` 赋值两次。

标签：`js::conditionals`

**卡 7**
正面：
What happens when you run `total = 5;` and `total` was never declared with `let` or `const`?
┄┄┄┄┄┄┄┄
如果 `total` 从来没有用 `let` 或 `const` 声明过，运行 `total = 5;` 会发生什么？

背面：
In non-strict mode (what you get by default when you run a plain `.js` file with `node`), there is no error: JavaScript silently creates a global variable `total`. In strict mode, the same line throws `ReferenceError: total is not defined`. Always declare a variable with `let` or `const` before using it.
┄┄┄┄┄┄┄┄
在非严格模式下（用 `node` 运行普通 `.js` 文件时默认就是这个模式），不会报错：JavaScript 会悄悄创建一个全局变量 `total`。在严格模式（strict mode）下，同一行会报 `ReferenceError: total is not defined`。变量一律先用 `let` 或 `const` 声明，再使用。

标签：`js::variables js::errors`
