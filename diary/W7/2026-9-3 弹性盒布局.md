# 2026-9-3(W7D4)
## 今日主题:弹性盒布局 Flexbox
## 学了什么:
Flexbox 所有属性其实只回答**两个问题**。你把这两个问题记死，属性就自动各就各位了：

**问题一：这属性设在谁身上？**——容器（main）还是单个孩子（div）？
**问题二：它管哪条轴？**——主轴（默认横）还是交叉轴（默认竖）？

先按"设在谁身上"切第一刀，这是最大的一刀。

**一、容器属性（设在 flex 容器上，定所有孩子的大局）**

| 属性 | 一句话 | 管哪轴 |
|---|---|---|
| `display: flex` | 总开关，开启 flex 模式 | — |
| `flex-direction` | 主轴朝哪：row 横 / column 竖 | 定义主轴 |
| `flex-wrap` | 一行塞不下，要不要换行 | — |
| `justify-content` | 沿主轴怎么分布（挤左/右/中/散开） | 主轴 |
| `align-items` | 沿交叉轴怎么对齐（上/下/中/拉伸） | 交叉轴 |

**二、弹性项属性（设在单个孩子上，只管它自己）**

| 属性 | 一句话 | 管哪轴 |
|---|---|---|
| `align-self` | 交叉轴上单独破例，不跟大伙儿一致 | 交叉轴 |
| `flex-grow` | 有富余空间，我要不要长大 | 主轴 |
| `flex-shrink` | 空间不够，我要不要缩小 | 主轴 |
| `flex-basis` | 我的基准大小（长/缩之前的起点） | 主轴 |
| `flex` | 上面 grow/shrink/basis 仨的简写 | 主轴 |
| `order` | 我排第几（改显示顺序） | 主轴 |

**三个记忆抓手，比背表管用：**

1. **名字带 `justify` 的管主轴，带 `align` 的管交叉轴。** 今天给过你了，这是分辨"管横还是管竖"的万能钥匙。
2. **`grow` / `shrink` / `basis` 是一家三口**，全在管"孩子在主轴上的尺寸"——长大、缩小、起点。`flex` 就是把它仨打包写一行。
3. **`flex-direction` 是那个"翻转全局"的开关**：它一改主轴朝向，上面所有"主轴/交叉轴"跟着转。主轴变竖了，`justify-content` 就从管横向变成管竖向。所以它要**最先**理解——它是其他属性的地基。

再往上抽一层，容器属性和弹性项属性的分工，就是今天你**亲眼看到**的那件事：**容器属性定大局**（`align-items` 让所有 div 一起对齐），**弹性项属性开小灶**（`align-self` 让第三个 div 单独破例）。一个管全体，一个管个别。

## 卡壳的点:

**卡1**
- 正面：`display: flex` 加在容器上，它改变的是什么？容器"对外"的身份变了吗？
- 背面：它把容器**内部**切换成 flex 排版模式，管的是容器如何摆放它的子元素（默认横向排列）。容器**对外**的身份不变——原本是块级就还是块级，在页面上仍独占一行。
- 标签：CSS / Flexbox

**卡2**
- 正面：一个块级元素在页面上的排布特点是什么？
- 背面：独占一行，与相邻元素纵向堆叠，不和其他元素挤在同一行。
- 标签：CSS / 布局基础

**卡3**
- 正面：给父元素改大它自己的 margin 数值，会让父子间的 margin 合并"消失"吗？和加 padding/border 有何不同？
- 背面：不会。改 margin 数值不影响是否合并（两个 margin 仍直接相邻），只改变合并后的取值（取较大者）。加 padding/border 会在两者之间插入有厚度的实体，隔断相邻关系，从而阻止合并。
- 标签：CSS / 盒模型

**卡4**
- 正面：flex 容器里有哪两条轴？默认各朝什么方向？弹性项沿哪条轴排列？
- 背面：主轴（main axis）和交叉轴（cross axis）。默认主轴水平、交叉轴垂直，两轴互相垂直。弹性项默认沿主轴方向排列。
- 标签：CSS / Flexbox

**卡5**
- 正面：`justify-content` 和 `align-items`/`align-self` 分别控制哪条轴？怎么一眼分辨一个 flex 对齐属性管哪条轴？
- 背面：`justify-content` 管主轴，`align-items`/`align-self` 管交叉轴。分辨法：名字带 `justify` 的管主轴，带 `align` 的管交叉轴。
- 标签：CSS / Flexbox

**卡6**
- 正面：flex 属性里，哪些设在容器上、哪些设在单个弹性项上？两者作用范围有何不同？
- 背面：设在容器上的（如 `display`/`flex-direction`/`justify-content`/`align-items`/`flex-wrap`）管全体子元素的大局；设在单个弹性项上的（如 `align-self`/`flex-grow`/`flex-shrink`/`flex-basis`/`order`）只管该元素自己。典型对比：`align-items` 让所有项一起对齐，`align-self` 让单个项破例。
- 标签：CSS / Flexbox

**卡7**
- 正面：给一个弹性项写了 `align-self: stretch` 却没被拉伸，最可能的原因是什么？
- 背面：该元素在交叉轴方向的尺寸被写死了（如 `height: 50px`）。固定尺寸会挡住 stretch 的拉伸；要让 stretch 生效，需不固定该方向尺寸（如 `height: auto` 或干脆不设 height）。
- 标签：CSS / Flexbox
