**卡 1**
正面：
How is the specificity of `:where(...)` calculated? How is it different from `:is(...)`?
`:where(...)` 的特异性怎么算？跟 `:is(...)` 有什么区别？
背面：
`:where()` always contributes 0 specificity, no matter what is inside its parentheses, even an id. `:is()` takes the specificity of the most specific item inside its parentheses. Both match exactly the same elements; only the specificity differs. Parts of the selector outside the parentheses still count as usual: `.list :where(#a)` = 1 class. Example: `:where(#a, .b)` = 0, `:is(#a, .b)` = 1 id. This makes `:where()` suitable for default styles that should be easy to override, such as a reset.
`:where()` 贡献的特异性永远是 0，括号里写什么都一样，写了 id 也是 0。`:is()` 取括号里特异性最高的那一项。两者匹配到的元素完全一样，区别只在特异性。括号外面的部分照常算分：`.list :where(#a)` 算 1 个 class。例：`:where(#a, .b)` 是 0，`:is(#a, .b)` 是 1 个 id。所以 `:where()` 适合写想让别人轻松覆盖的默认样式，比如 Reset。
标签：`css::selectors css::specificity`

**卡 2**
正面：
What is the difference between `p:only-child` and `p:only-of-type`? What does "type" mean here?
`p:only-child` 和 `p:only-of-type` 有什么区别？这里的「type」指什么？
背面：
`p:only-child`: the `p` is its parent's only child; a sibling of any tag breaks it. `p:only-of-type`: the `p` is the only `p` among its siblings; siblings with other tags are allowed. "Type" means the tag name, not the class. Example: in `<div><h4></h4><p></p></div>`, the `p` matches `:only-of-type` but not `:only-child`. `:only-of-type` = `:first-of-type` and `:last-of-type` both true; likewise `:only-child` = `:first-child` and `:last-child` both true.
`p:only-child`：这个 `p` 是父元素唯一的子元素，旁边有任何标签的兄弟都不行。`p:only-of-type`：这个 `p` 是兄弟里唯一的 `p`，旁边有别的标签没关系。「type」指标签名，跟 class 无关。例：`<div><h4></h4><p></p></div>` 里的 `p` 满足 `:only-of-type`，不满足 `:only-child`。`:only-of-type` 等于 `:first-of-type` 和 `:last-of-type` 同时成立；同理，`:only-child` 等于 `:first-child` 和 `:last-child` 同时成立。
标签：`css::selectors`

**卡 3**
正面：
Where does `justify-content: flex-start` put the items when `flex-direction` is `row-reverse`? When it is `column`?
当 `flex-direction` 是 `row-reverse` 时，`justify-content: flex-start` 把项目放在哪？是 `column` 时呢？
背面：
`flex-start` means the start of the main axis, not "the left side". With `row-reverse`, the main axis runs right to left, so the items are packed on the right (read from the left: 3 2 1). With `column`, the main axis runs top to bottom, so `flex-start` is the top and `flex-end` is the bottom.
`flex-start` 指的是主轴的起点，不是「左边」。`row-reverse` 时主轴从右往左走，所以项目挤在右边（从左往右读是 3 2 1）。`column` 时主轴从上往下走，`flex-start` 是顶部，`flex-end` 是底部。
标签：`css::flexbox`

**卡 4**
正面：
When does `stretch` (the default alignment) actually stretch a flex item or a grid item? What size does the item take when it is not stretched?
`stretch`（默认的对齐方式）什么时候才会真的把 flex 项目或 grid 项目拉伸？不拉伸时，项目是多大？
背面：
Flex: `align-items: stretch` works only along the cross axis, and only when the item's size in that direction is `auto`. A fixed size (e.g. `height: 40px` in a `row` container) stops it. It never acts on the main axis: in a `column` container, an item's height is just its content height. Grid: by default, items stretch in both directions (via `justify-items` and `align-items`), with the same "only if that size is `auto`" condition. In both cases, an item that is not stretched shrinks to its content size in that direction.
Flex：`align-items: stretch` 只沿交叉轴拉伸，而且只在项目那个方向的尺寸是 `auto` 时才拉。写死尺寸就拉不动（例：`row` 容器里写了 `height: 40px`）。它从不作用于主轴：`column` 容器里，项目的高度就是内容的高度。Grid：默认两个方向都拉伸（由 `justify-items` 和 `align-items` 控制），条件同样是那个方向的尺寸为 `auto`。两种布局里，不拉伸的方向，项目都会缩回内容大小。
标签：`css::flexbox css::grid`

**卡 5**
正面：
In a grid, what do `justify-items` / `align-items` on the container do? How do `justify-self` / `align-self` relate to them? Which prefix is horizontal and which is vertical?
在 grid 里，写在容器上的 `justify-items` / `align-items` 起什么作用？`justify-self` / `align-self` 跟它们是什么关系？哪个前缀管横向，哪个管纵向？
背面：
Written on the container, they set a default alignment for every item at once. Each item moves only inside its own cell, never into other cells. `justify-self` / `align-self` on a single item overrides that default for that item only. `justify-` is horizontal and `align-` is vertical (in normal horizontal text). Contrast with flex: `justify-content` pushes the whole row of items as a group.
写在容器上，等于一次性给每个项目定一个默认的对齐方式。每个项目只在自己的格子里挪动，不会跑进别的格子。在单个项目上写 `justify-self` / `align-self`，只覆盖这一个项目的默认值。`justify-` 管横向，`align-` 管纵向（在普通的横排文字下）。对比 flex：`justify-content` 是把一整排项目当成一组来推。
标签：`css::grid`

**卡 6**
正面：
In a grid, what do `grid-column: 1 / -1` and `grid-column: span 2` mean? What does `grid-auto-flow: dense` do, and what is its downside?
在 grid 里，`grid-column: 1 / -1` 和 `grid-column: span 2` 分别是什么意思？`grid-auto-flow: dense` 有什么作用，有什么副作用？
背面：
`1 / -1`: from line 1 to the last line (negative numbers count from the end), so the item spans the whole row. `span 2`: the item covers 2 cells, starting wherever it is auto-placed. `dense`: later items backfill empty holes left earlier in the grid. Downside: the visual order no longer matches the HTML order, while the Tab key and screen readers still follow the HTML order.
`1 / -1`：从第 1 条线到最后一条线（负数从末尾往回数），所以横跨整行。`span 2`：跨 2 格，从它被自动放到的位置开始。`dense`：后面的项目会回头填进前面留下的空洞。副作用：画面上的顺序和 HTML 里的顺序不一致了，但 Tab 键和读屏软件仍然按 HTML 顺序走。
标签：`css::grid css::accessibility`

**卡 7**
正面：
You write `text-shadow: 3px 3px 4px 2px gray;`. What happens, and why? What is the general rule behind it?
写了 `text-shadow: 3px 3px 4px 2px gray;`，会发生什么？为什么？背后的通用规则是什么？
背面：
No shadow at all. `text-shadow` has no spread value (only x offset, y offset, blur and color; `box-shadow` is the one with spread), so the 4th length makes the value invalid. General rule: if any part of a declaration's value is invalid, the browser discards the whole declaration, including the parts that were valid. In Safari's styles panel, that line is struck through with a warning icon.
完全没有阴影。`text-shadow` 没有扩散值（只有横向偏移、纵向偏移、模糊和颜色；有扩散值的是 `box-shadow`），所以第 4 个长度让整个值不合法。通用规则：一个声明的值里只要有一部分不合法，浏览器就丢掉整条声明，写对的部分也一起作废。在 Safari 的样式面板里，这一行会被划掉，旁边有警告图标。
标签：`css::syntax css::shadows`
