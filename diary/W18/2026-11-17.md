**三、常用数组方法讲解 4 节**

1. `arr.indexOf(值, 起点)`：返回第一次出现的索引，找不到返回 `-1`。从起点开始找，但返回的索引仍然从整个数组开头数。
2. `arr.splice(起点, 删几个, 要插入的…)`：
   - 先删再插，**直接改原数组**。
   - 返回值永远是被删元素组成的数组，没删就是 `[]`。
   - 省略「删几个」就从起点一直删到末尾；`splice(0)` 清空数组。
3. 按值删除的固定写法：先 `indexOf` 找位置，判断 `!== -1` 之后再 `splice(index, 1)`。
4. `arr.includes(值, 起点)`：返回 `true` 或 `false`，比较用的是 `===`。所以区分大小写，数字 `2` 和字符串 `"2"` 也不算同一个。
5. 浅拷贝有三种写法：`arr.slice()`、`[...arr]`、`[].concat(arr)`。
   - 拷贝出来的是新的外层数组，`copy === arr` 是 `false`，对拷贝增删元素不影响原数组。
   - 里面套的小数组不会被复制，原数组和拷贝共用同一个。

**四、整理速查表时理清的几点**

1. 字符串和数组的同名方法规则基本一样：索引从 0 数，找不到返回 `-1`，`slice` 包括开始、不包括结束。
2. **字符串的 `indexOf`/`includes` 找片段，数组的只认整个元素**：`["hello"].includes("ell")` 是 `false`。
3. 学过的会改原数组的方法有 6 个：`push` `pop` `shift` `unshift` `splice` `reverse`。字符串一个都没有。
4. `join()` 不传分隔符时用逗号连接；只有 `join("")` 才什么都不夹。fCC 复习页把这点写错了。

```javascript
function addItem(arr, item) {

const r1 = addItem(cart, "milk");
const r2 = addItem(cart, "");
```
1. What do the two calls print, in order?
2. What are `r1` and `r2`? Why?

┄┄┄┄┄┄┄┄

3. 最后 `cart` 是什么？

背面：
1. `milk added.`, then `Empty item.`. In the first call `"milk" === ""` is false, so the whole `if` block is skipped.
2. Both are `undefined`. Every function call hands back a value. If you don't say which value, it is `undefined`. That covers both no `return` at all (the first call runs to the closing `}`) and a bare `return;` (the second call).
3. `["milk"]`. In the second call, `return;` stops the function before `push` runs.

┄┄┄┄┄┄┄┄

**卡 2**

正面：
```javascript
function golfScore(par, strokes) {
  if (strokes <= par - 2) {
    return "Eagle";
  } else if (strokes === 1) {
    return "Hole-in-one!";
  } else if (strokes === par - 1) {
    return "Birdie";
  } else if (strokes >= par) {
    return "Par or worse";
  }
}
```
1. What does `golfScore(3, 1)` return? Why is that a bug?
2. How should the first two branches be ordered? What is the general rule?
3. Why is it better to end the chain with a plain `else` instead of `else if (strokes >= par)`?

┄┄┄┄┄┄┄┄

1. `golfScore(3, 1)` 返回什么？为什么这是 bug？
2. 前两个分支应该怎么排？通用规则是什么？
3. 为什么链的最后用单独的 `else`，比用 `else if (strokes >= par)` 好？

背面：
1. `"Eagle"`. `1 <= 3 - 2` is true, so the first branch runs and the Hole-in-one branch is never reached.
2. Check `strokes === 1` first. In an `if / else if` chain only the first true branch runs, so when conditions overlap, put the more specific one first.
3. A plain `else` catches everything the earlier branches missed, so the function always returns a string. With `else if`, when no condition is true (e.g. `golfScore(4, 3.5)`), the function runs to the closing `}` and returns `undefined`.

┄┄┄┄┄┄┄┄

1. `"Eagle"`。`1 <= 3 - 2` 是 true，第一个分支先跑了，Hole-in-one 分支根本轮不到。
2. 先判断 `strokes === 1`。`if / else if` 链里只有第一个为 true 的分支会跑，所以条件有重叠时，更特殊的放前面。
3. 单独的 `else` 会接住前面所有分支漏掉的情况，函数一定返回字符串。用 `else if` 的话，所有条件都不满足时（比如 `golfScore(4, 3.5)`），函数走到 `}`，返回 `undefined`。

标签：`js::conditionals js::functions`
