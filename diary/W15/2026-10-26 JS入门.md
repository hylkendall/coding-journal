### JavaScript 入门（理论，4 课）

**什么是 JavaScript，如何与 HTML 和 CSS 配合使用？**
三者分工是：HTML 管结构，CSS 管样式，JS 管行为和交互。JS 通过 `<script>` 元素接进网页，可以直接写在标签里，也可以用 `src` 引入外部 `.js` 文件。JS 不只在浏览器里跑，用 Node.js 也能在电脑上直接运行，你今天就是这么跑的。

**什么是数据类型，JavaScript 中有哪些不同的数据类型？**
JS 有 8 种数据类型：Number、BigInt、String、Boolean、Undefined、Null、Symbol、Object。明天的数据类型课会深入讲。

**什么是变量，JavaScript 变量命名原则是什么？**
变量就是给一个值起名字、存起来。命名规则：
- 只能用字母、数字、`_`、`$`，而且不能以数字开头；
- 区分大小写；
- 不能用 `let`、`const` 这类保留字。

习惯用驼峰命名（camelCase，比如 `botLocation`），名字要能看出存的是什么。

**在变量声明、赋值和重赋值时，let 和 const 有什么不同？**
`let` 可以先声明、后赋值（`let bot;` 这时 bot 的值是 `undefined`），之后还可以重新赋值。`const` 必须在声明时就赋值，之后不能重新赋值，否则报 `TypeError: Assignment to constant variable.`。
重新赋值（`name = ...`）和重新声明（再写一遍 `let name = ...`）是两回事，在同一作用域里重新声明会报 SyntaxError。
业内习惯：默认用 `const`，只有后面会被重新赋值的变量才用 `let`。
英文：declare / assign / reassign / redeclare。

### 字串简介（理论，3 课）

**什么是 JavaScript 中的字符串，什么是字符串不可变性？**
字符串是用引号包起来的一串字符。字符串不可变（immutable），意思是里面的字符不能原地修改：
- `str[0] = "M"` 在 fCC 编辑器里会报 TypeError；在本地 node 里不报错，但也改不了（静默失败）。
- `[0]` 只负责定位第 0 个字符（从 0 开始数），`=` 才是写入。

要换内容，只能把一个新字符串整体重新赋值给变量。用纸条比方：纸条上的字改不了，但用 `let` 可以把整张纸条换掉；用 `const` 的话，连纸条也换不了。
英文：immutable = im-（不）+ mutable（可变的），mutate 就是"改变"。

**什么是字符串连接，如何用变量连接字符串？**
用 `+` 拼接字符串和变量，比如 `"My name is " + bot + "."`。`a += b` 是 `a = a + b` 的简写：先造出一个新字符串，再重新赋值给 a，原来的字符串没被改过。证据是：变量用 `const` 声明时，`+=` 会报和重新赋值一样的错。
英文：concatenate / concatenation。

**console.log 有什么用途，它是如何工作的？**
它把括号里的内容打印到控制台（浏览器的开发者工具，或者 Node 的终端），用来检查代码运行时某个值到底是什么。代码里只有 `console.log` 的内容会显示出来。
顺带的简版：写成 `主人.名字()` 的是方法，直接写 `名字()` 的是函数。`log` 是挂在 `console` 上的方法。模块 5「对象」会正式讲。

### 理解代码清晰度（理论，2 课）

**分号在 JavaScript 和其他编程中的作用是什么？**
分号标记一条语句结束。漏写时 JS 会自动补（ASI），但有两种情况会补错：
- **坑一**：`return` 后面直接换行，JS 当场补成 `return;`，结果返回 `undefined`。
- **坑二**：下一行以 `(` 开头时，JS 不补分号，把两行粘成一句，变成 `"Hello"(...)`，报 `TypeError: "Hello" is not a function`。

结论：分号自己写；`return` 要返回的东西，开头和 `return` 写在同一行。
英文：IIFE = Immediately Invoked Function Expression，invoke 就是"调用"。

**什么是 JavaScript 中的注释，应该什么时候使用？**
单行注释用 `//`，多行注释用 `/* ... */`。注释用来解释"为什么这么写"，而不是重复"这行在干什么"；显而易见的代码不用写注释。调试时也可以用注释临时让某几行不执行。

```
In JavaScript, can you change a single character of an existing string, for example with str[0] = "M"? What happens if you try?

在 JavaScript 中，能否修改已有字符串里的单个字符（例如 str[0] = "M"）？尝试修改会发生什么？
```

```
No. Strings are immutable (im- = not, mutable = changeable): their characters cannot be changed in place. 不能。字符串是不可变的（immutable）：字符不能原地修改。严格模式下（如 fCC 编辑器）抛出 TypeError: Cannot assign to read only property '0' of string；非严格模式下（如用 node 直接运行普通 .js 文件）静默失败，字符串保持原样。
```

### 卡 2｜字符串不可变 vs const

正面
```
What is the difference between "strings are immutable" and "a const variable cannot be reassigned"?
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
"字符串不可变"和"const 变量不能重新赋值"有什么区别？
```
背面
```
Immutability is about the value: the characters inside a string can't be changed. const is about the variable: it can't be reassigned to a different value. A string variable declared with let can be reassigned to a new string, but its characters still can't be changed in place.
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
不可变针对的是值：字符串内部的字符不能改（纸条上的字改不了）。const 针对的是变量：变量不能重新赋值为另一个值（纸条不能换）。用 let 声明的字符串变量可以重新赋值为新字符串，但字符依然不能原地修改。
```
标签：`js::strings` `js::variables`

### 卡 3｜+= 的本质

正面
```
Given let greeting = "Hello";, what does greeting += ", John!"; actually do? Why is the original string "Hello" not modified?
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
已知 let greeting = "Hello";，greeting += ", John!"; 实际做了什么？为什么原字符串 "Hello" 没有被修改？
```
背面
```
It is shorthand for greeting = greeting + ", John!";. The + creates a brand-new string "Hello, John!", then = reassigns greeting to it. The variable changes; the original string "Hello" is never edited. (Evidence: if greeting is declared with const, += throws TypeError: Assignment to constant variable.)
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
它是 greeting = greeting + ", John!"; 的简写。+ 先拼出一个全新的字符串 "Hello, John!"，再用 = 把它重新赋值给 greeting。变的是变量，原字符串 "Hello" 从未被修改。（证据：若 greeting 用 const 声明，+= 会报 TypeError: Assignment to constant variable.）
```
标签：`js::strings` `js::variables`

### 卡 4｜默认 const

正面
```
When declaring a variable, when should you use const and when should you use let? What is the deciding question?
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
声明变量时，什么时候用 const、什么时候用 let？判断依据是什么？
```
背面
```
Use const by default; use let only if the variable will be reassigned later (a widely used convention, not a syntax rule). Deciding question: "Is this variable reassigned anywhere later?" const tells readers the variable is never reassigned, and JS throws an error if you reassign it by accident.
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
默认用 const；只有之后要重新赋值的变量才用 let（这是通行的写法习惯，不是语法规定）。判断依据："这个变量后面有没有被重新赋值？" const 告诉读代码的人它不会被重新赋值；万一误改，JS 会直接报错拦住。
```
标签：`js::variables`

### 卡 5｜重新赋值 vs 重新声明

正面
```
What is the difference between reassigning and redeclaring a variable? Give an example of each using let name.
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
重新赋值和重新声明有什么区别？分别用 let name 举例。
```
背面
```
Reassign: name = "Messica"; gives an existing variable a new value (allowed with let, not with const). Redeclare: writing let name = "Messica"; again in the same scope declares the same name a second time, which throws a SyntaxError.
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
重新赋值：name = "Messica"; 给已有变量换一个值（let 允许，const 不允许）。重新声明：在同一作用域（scope）中再写一次 let name = "Messica";，同名变量被声明第二次，会报 SyntaxError。
```
标签：`js::variables`

### 卡 6｜ASI 坑一：return 后换行

正面
```
Why does getValue() return undefined instead of the object?

function getValue() {
  return
  { value: 42 };
}
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
为什么 getValue() 返回 undefined，而不是那个对象？（代码同上）
```
背面
```
ASI (Automatic Semicolon Insertion) inserts a semicolon right after return when a line break follows, turning it into return; so nothing is returned. Fix: start the returned value on the same line as return (return {).
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
ASI（自动插入分号）在 return 后面紧跟换行时，直接补成 return;，于是什么都没返回（undefined）。修法：要返回的值，开头必须和 return 写在同一行（return {）。
```
标签：`js::syntax`

### 卡 7｜ASI 坑二：下一行以 ( 开头

正面
```
Why does this code throw TypeError: "Hello" is not a function?

const message = "Hello"
(function () {
  console.log(message);
})()
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
为什么这段代码会报 TypeError: "Hello" is not a function？（代码同上）
```
背面
```
There is no semicolon after "Hello", and the next line starts with (, which can continue the previous expression, so ASI does not insert one. JS reads it as "Hello"(...), calling the string as if it were a function. Fix: end each statement with ; yourself.
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
"Hello" 后面没有分号，而下一行以 ( 开头，( 可以接续上一行的表达式，所以 ASI 不补分号。JS 把两行读成 "Hello"(...)，也就是把字符串当函数调用。修法：每条语句末尾自己写分号。
```
标签：`js::syntax`

### 卡 10｜读报错的顺序

正面
```
When reading a Node.js error, in what order should you scan it, and which part states the actual cause?
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
读 Node.js 报错时按什么顺序看？真正的原因写在哪？
```
背面
```
1) file name and line number → 2) the code line and the ^ marking the position → 3) the line starting with the error type. The cause is the text after the colon; the same error type (e.g. TypeError) can have different causes. In the stack trace, only the "at" line containing your own file name (:line:column) matters; ignore lines starting with node:internal.
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
① 文件名和行号 → ② 出错的代码行和 ^ 指的位置 → ③ 以错误类型开头的那一行。真正的原因是冒号后面那句；同一种错误类型（如 TypeError）可以有完全不同的原因。调用栈里只看带你自己文件名的那条 at（:行:列），node:internal 开头的忽略。
```
标签：`js::debugging`
