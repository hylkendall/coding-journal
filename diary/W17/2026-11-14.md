## W17D6 总结（11/14）· 模块 3 函数考核

**一、冷启动**

1. 默认参数只接管 `undefined`。`greet(null)` 打印 `Hi, null`；函数里的 `console.log` 在调用那一行就打印。
2. **有没有 `let`，决定新建还是改旧的**：
   - 有 `let`（或 `const`）：新建一个变量，只活在离它最近的那对花括号里
   - 没有 `let`：去找一个已有的变量来改，先在当前花括号里找，找不到就一层层往外找，改了就一直留着，函数结束也不还原
   - 对照：`bump(count)` 里的形参是函数自己的变量，外面不动；算牌的全局 `count` 每次调用都被改，所以会累加

**二、苏格拉底问答（1–4 全对，5 找到 2/3）**

1. `return` 一执行函数就结束，后面的代码不再运行。
2. `price(100, 0)`：`0` 是真传进来的值，默认值不接管（`||` 才会把 `0` 换掉）。`price()`：`undefined` 参与运算得 `NaN`。
3. 函数体在**调用时**才执行，读的是那一刻外层变量的值。
4. `const isPassing = score => score >= 60;`：比较本身就是 `true`/`false`，直接返回。
5. 三个 bug：
   - 默认值 `"false"` 是非空字符串，truthy，`if` 会进去 → 用布尔 `false`
   - 没有 `return` → 返回 `undefined`
   - if 里的 `let result` 是新变量，外面的 `result` 没被改 → 去掉 `let`
   - 另外两点：`true === "true"` 是 `false`（类型不同）；不同花括号里各 `let` 一次同名变量不报错，同一对花括号里声明两次才报错

**三、迷你项目：停车场小票 ✅**

1. **定义的括号里放名字（形参），调用的括号里放值（实参）**。`(getFee()) =>` 是把调用写进了定义，`SyntaxError`。
2. **单个 `=` 只有在函数定义的括号里才是默认值**，其他地方全是赋值。调用里写 `isMember = false` 会把传进来的 `true` 顶掉。
3. **转交参数**：外层函数收到的形参，原样传给内层就行，写成 `getFee(hours, isMember)`。
4. **提前 return**：先把特殊情况（0 小时）`return` 掉，后面就不需要 `else`。`if { }` 和 `else if` 之间不能插语句，插了报 `SyntaxError: Unexpected token 'else'`。
5. **中间变量**：重复的算式存进变量（`fee`、`capped`、`hours`），每个变量只做一件事；存进去不再改的用 `const`。
6. `++n;` 单独一行就已经加了 1，不用再写 `n = ++n`。
7. 用到的老知识：`Math.ceil` 向上取整，`slice(0, 2)` + `"*".repeat(...)` + `slice(-2)` 打码，`toFixed(2)` 保留两位。

**卡 1**

正面：
```javascript
let total = 0;

function add(n) {
  if (n > 0) {
    let total = n;
  }
  total = total + n;
  return total;
}

console.log(add(5));
console.log(add(3));
console.log(total);
```
1. What do the three lines print?
2. Inside `add`, which `total` does each of these lines use?
   a. `let total = n;`
   b. `total = total + n;`
3. What rule tells you whether a line creates a new variable or changes an existing one?

┄┄┄┄┄┄┄┄

1. 三行分别打印什么？
2. 在 `add` 里，下面两行用的分别是哪个 `total`？
   a. `let total = n;`
   b. `total = total + n;`
3. 用什么规则判断一行代码是新建变量，还是修改已有的变量？

背面：
1. `5`, `8`, `8`.
2. a. A new `total` that exists only inside the `if` braces. It is gone when the `if` ends, so it changes nothing here.
   b. The global `total`. This line has no `let`, so it changes the global variable, and the change stays after the function returns: the second call starts from `5`.
3. Look for `let`. With `let` (or `const`), a new variable is created, and it exists only inside the nearest pair of curly braces. Without `let`, an existing variable is changed: JavaScript looks in the current braces first, then each outer level, and changes the first one it finds.

┄┄┄┄┄┄┄┄

1. `5`、`8`、`8`。
2. a. 一个新的 `total`，只存在于 if 的花括号里。if 一结束它就没了，所以在这里什么都没改变。
   b. 全局的 `total`。这一行没有 `let`，所以改的是全局变量，而且函数返回后改动仍然保留：第二次调用从 `5` 开始加。
3. 看有没有 `let`。有 `let`（或 `const`）就是新建变量，它只存在于离它最近的那对花括号里。没有 `let` 就是修改已有的变量：JavaScript 先在当前花括号里找，找不到再一层层往外找，改的是找到的第一个。

**卡 2**

正面：
```javascript
const formatYuan = (getFee()) => getFee().toFixed(2);

function getReceipt(hours, isMember = false) {
  return getFee(hours, isMember = false);
}
```
1. Why does the `formatYuan` line throw a `SyntaxError`? How should it be written?
2. In `getReceipt`, what does `isMember = false` inside the call to `getFee` do? What does `getFee` receive when `getReceipt(3, true)` is called? How do you fix it?
3. A single `=`: where does it mean a default value, and what does it mean everywhere else?

┄┄┄┄┄┄┄┄

1. 为什么 `formatYuan` 这一行会报 `SyntaxError`？应该怎么写？
2. 在 `getReceipt` 里，调用 `getFee` 时括号里的 `isMember = false` 做了什么？调用 `getReceipt(3, true)` 时 `getFee` 收到的是什么？怎么改？
3. 单个 `=`：在哪里表示默认值？在其他地方表示什么？

背面：
1. The parentheses of a function definition hold parameter names, not function calls. Give the incoming number a name and use that name in the body: `const formatYuan = yuan => yuan.toFixed(2);`. Where the number comes from is decided by the caller: `formatYuan(getFee(3))` or `formatYuan(8)`.
2. It is an assignment: it first sets `isMember` to `false`, then passes `false` to `getFee`. So `getFee` receives `false`, and the `true` passed to `getReceipt` is overwritten. Fix: pass the parameter on as it is: `getFee(hours, isMember)`.
3. Only in the parentheses of a function definition does `=` mean a default value (used when the argument is `undefined`). Everywhere else, including the parentheses of a call, `=` is assignment: the value on the right is stored in the variable on the left.

┄┄┄┄┄┄┄┄

1. 函数定义的括号里放的是形参名字，不能放函数调用。给传进来的数起个名字，函数体里用这个名字：`const formatYuan = yuan => yuan.toFixed(2);`。这个数从哪来，由调用的人决定：`formatYuan(getFee(3))` 或 `formatYuan(8)`。
2. 它是一句赋值：先把 `isMember` 改成 `false`，再把 `false` 传给 `getFee`。所以 `getFee` 收到的是 `false`，传给 `getReceipt` 的 `true` 被覆盖了。改法：把形参原样转交：`getFee(hours, isMember)`。
3. 只有写在函数定义的括号里，`=` 才表示默认值（实参是 `undefined` 时使用）。其他地方，包括调用的括号里，`=` 都是赋值：把右边的值存进左边的变量。

标签：`js::functions`

**卡 3**

正面：
```javascript
function getFee(hours) {
  if (hours === 0) {
    return 0;
  }
  const fee = (hours - 1) * 5 + 8;
  return fee;
}
```
1. Why is no `else` needed after the `if`?
2. Without the `if`, what would `getFee(0)` return?
3. Can a statement such as `const fee = ...;` be written between an `if { }` block and its `else if`?

┄┄┄┄┄┄┄┄

1. 为什么 `if` 后面不需要 `else`？
2. 如果没有这个 `if`，`getFee(0)` 会返回什么？
3. `if { }` 块和它的 `else if` 之间，能写 `const fee = ...;` 这样的语句吗？

背面：
1. `return` ends the function immediately. When `hours` is `0`, the function returns at the `if`, so the code below only runs when `hours` is not `0`. This is called an early return: handle the special case first, then write the normal case.
2. `3`, because `(0 - 1) * 5 + 8` is `3`. The formula is only correct for 1 hour or more, so `0` has to be handled separately.
3. No. `else` must come right after the closing `}` of the previous block. Anything in between causes `SyntaxError: Unexpected token 'else'`.

┄┄┄┄┄┄┄┄

1. `return` 一执行函数就立刻结束。`hours` 是 `0` 时，函数在 `if` 那里就返回了，所以下面的代码只会在 `hours` 不是 `0` 时运行。这种写法叫提前 return：先处理特殊情况，再写正常情况。
2. `3`，因为 `(0 - 1) * 5 + 8` 等于 `3`。这个算式只对 1 小时及以上成立，所以 `0` 必须单独处理。
3. 不能。`else` 必须紧跟在上一个块的 `}` 后面，中间插任何东西都会报 `SyntaxError: Unexpected token 'else'`。

标签：`js::functions js::conditionals`

**卡 4**

正面：
```javascript
function check(isMember = "false") {
  if (isMember) {
    return "discount";
  }
  return "full price";
}
```
1. What does `check()` return? Why?
2. What does `true === "true"` evaluate to? Why?
3. How should the default value and the condition be written so that `check()` returns `"full price"` and `check(true)` returns `"discount"`?

┄┄┄┄┄┄┄┄

1. `check()` 返回什么？为什么？
2. `true === "true"` 的结果是什么？为什么？
3. 默认值和条件应该怎么写，才能让 `check()` 返回 `"full price"`、`check(true)` 返回 `"discount"`？

背面：
1. `"discount"`. The default `"false"` is a non-empty string, and every non-empty string is truthy, so the `if` block runs.
2. `false`. One is a boolean and the other is a string. `===` does not convert types, so values of different types are never equal.
3. Use the boolean `false` without quotes as the default, `isMember = false`, and keep the condition as `if (isMember)`. `if` already checks truthy or falsy, so no comparison is needed.

┄┄┄┄┄┄┄┄

1. `"discount"`。默认值 `"false"` 是非空字符串，所有非空字符串都是 truthy，所以会进入 if 块。
2. `false`。一个是布尔值，一个是字符串。`===` 不做类型转换，类型不同的值永远不相等。
3. 默认值用不带引号的布尔值 `false`，写成 `isMember = false`，条件保持 `if (isMember)`。`if` 本身就会判断 truthy 还是 falsy，不需要再比较。

标签：`js::functions js::conditionals js::operators`





**函数套函数容易糊涂**，给你三个办法：

1. **读的时候从里往外读**。`formatYuan(getFee(hours, isMember))`：最里面的 `getFee(...)` 先算，算出一个数，比如 `14.4`，这个数再交给外面的 `formatYuan`。每一层都是"先变成一个值，再往外递"。
2. **写的时候每个函数只管自己**。`formatYuan` 根本不知道 `getFee` 存在，它只管"进来一个数，叫它 `yuan`"。东西从哪来，是调用的人的事。你今天卡住的 `formatYuan(getFee())`，就是让一个函数去操心了别人的事。
3. **一糊涂就拆开**。把里层的结果先存进 `const`，再交给外层，你自己写的 `const hours = getHours(minutes);` 就是这么拆的。拆开不丢人，反而更好读。
