## W17D3 总结

**一、冷启动 ✅ 2/2**

1. 箭头函数留着花括号却没写 `return`，交出 `undefined`；`8 + undefined` 是 `NaN`。
2. 形参和外面的变量重名时，函数里改的是自己那个局部变量，外面的不受影响。

**二、贷款资格检查器 workshop ✅**

1. `if / else if` 从上往下查，碰到第一个 `true` 就执行那一档，后面不再看。能走到第三档，说明前两档都没过。
2. 所以顺序要从严到宽（duplex → condo → car）。要是把 car 放最前面，够 duplex 的人也会先被 car 那档截走。
3. 读题：英文原文 "a car loan only" 里，`only` 修饰的是 car loan，意思是"只够得上汽车贷款"。中文翻成"只检查"是错译。中文题干读不通时，对照英文原文。

**三、摄氏转华氏 lab ✅**

1. `Number(num * (9 / 5) + 32)` 外面那层多余：`*` 算出来一定是数字，`Number()` 只是把数字再转一遍，也过滤不了输入。
2. 规格写"接收一个数字参数"，是调用方的约定，不用自己加检查。返回 `"Error"` 会违反"应返回一个数字"。
3. `typeof NaN` 是 `"number"`，所以用 `typeof` 检查会漏掉 `NaN`，要抓它用 `Number.isNaN()`。

**四、算牌 lab ✅**

1. `case (2, 3, 4, 5, 6):` 只等于 `case 6:`。圆括号里用逗号隔开的一串值只取最后一个（逗号运算符，不用记）。
2. 多个值共用一段代码：把 `case` 叠起来，空 case 一路贯穿到同一个出口。
3. 没有 case 匹配，`switch` 直接跳过。7、8、9 不用写，`count = count;` 什么都没做。
4. `if (count > 0)` 后面直接写 `else`，不写 `else if (count <= 0)`。`else` 还保证每条路都有 `return`。
5. 开头的类型转换：方法是对的，靠 `<=` / `>=` 把字符串转成数字再比，`"8"` 进 `if`，`"J"` 变 `NaN` 走 `else`。但 `else` 那半不干活，而且规格已经保证了类型，所以整段删。
6. 全局 `count` 跨调用累积。自己测多组时，组与组之间写 `count = 0;` 归零。外面要给它重新赋值，所以用 `let`。

**五、读题和测试**

1. 用户故事分两类：一类是"你要做什么"（建函数、返回字符串），要写代码去满足；另一类是"你会收到什么"（参数类型），不用写代码，只要按它写形参和 `case` 的类型。
2. fCC 的测试就是一段调用你函数的代码。算牌的每条测试开头先 `count = 0;`，再连着喂牌，最后检查返回值。
3. 检查习惯：写完扫一遍，每行问一句"删掉它，结果会变吗？"不变就删。今天的 `Number()`、`count = count;`、`else if` 的条件，加上昨天的 `? true : false`，都是同一类。

The lab's user stories say `convertCtoF` should take a single numeric argument and should return a number.
1. Why is the `Number(...)` wrapper unnecessary? Does it make the function accept only numbers?

这个 lab 的用户故事说：`convertCtoF` 应该接收一个数字参数，应该返回一个数字。
1. 为什么外面那层 `Number(...)` 是多余的？它能让函数只接收数字吗？
2. 为什么不加一个检查，在输入不是数字时返回 `"Error"`？

┄┄┄┄┄┄┄┄

```javascript
switch (card) {
  case (2, 3, 4, 5, 6):
    count = count + 1;
    break;
}
```
1. Which value of `card` does this `case` match? Why?
2. How do you make `2`, `3`, `4`, `5` and `6` share the line `count = count + 1;`? Why does it work?

┄┄┄┄┄┄┄┄

1. 这个 `case` 能匹配上 `card` 的哪个值？为什么？
2. 怎么让 `2`、`3`、`4`、`5`、`6` 共用 `count = count + 1;` 这一行？为什么这样可行？

背面：
```javascript
case 2:
case 3:
case 4:
case 5:
case 6:
  count = count + 1;
  break;
```
1. Only `6`. In parentheses, values separated by commas evaluate to the last one (the comma operator), so this line is the same as `case 6:`.
2. Stack the cases as in the code above, with nothing between them. If `card` is `3`, the `switch` enters at `case 3:`. The cases below it are empty and have no `break`, so execution falls through to `count = count + 1;`, then `break` exits the `switch`.

┄┄┄┄┄┄┄┄

1. 只有 `6`。圆括号里用逗号隔开的一串值，结果是最后一个（逗号运算符），所以这一行等于 `case 6:`。

```javascript
switch (card) {
  // ...
  case 7:
  case 8:
  case 9:
    count = count;
    break;
  // ...
}

if (count > 0) {
  return count + " Bet";
} else if (count <= 0) {
  return count + " Hold";
}
```
1. Why can the whole `case 7` / `case 8` / `case 9` part be deleted?
2. What should `else if (count <= 0)` become? Why?

┄┄┄┄┄┄┄┄

2. `else if (count <= 0)` 应该改成什么？为什么？

┄┄┄┄┄┄┄┄

**卡 6**

正面：
```javascript
let count = 0;

function cardCounter(card) {
  // changes count by +1, 0 or -1, then returns a string such as "5 Bet"
}
```
fCC test: after the cards `2`, `3`, `4`, `5`, calling `cardCounter(6)` should return `"5 Bet"`.
1. Do you need to write this sequence of cards into your function? What does the test actually do?
2. Why does the count add up to `5`?
3. When you test several sequences in your own file, what must go between them? Why must `count` be declared with `let`?

┄┄┄┄┄┄┄┄

fCC 测试：在牌 `2`、`3`、`4`、`5` 之后，调用 `cardCounter(6)` 应该返回 `"5 Bet"`。
1. 需要把这串牌写进你的函数里吗？这条测试实际上做了什么？
2. 为什么计数会累加到 `5`？
3. 在自己的文件里测多组牌时，组与组之间必须写什么？为什么 `count` 必须用 `let` 声明？

背面：
1. No. A test is code that calls your function. This one runs `count = 0;`, then `cardCounter(2)` through `cardCounter(5)`, then checks that `cardCounter(6)` returns `"5 Bet"`.
2. `count` is a global variable, so every call changes the same `count` and the changes add up: five low cards, `+1` five times, gives `5`.
3. `count = 0;` to reset it; otherwise the next sequence continues from the previous total. `count` is given new values (reset from outside the function, `+1` or `-1` inside it), and a variable declared with `const` can't be given a new value, so it needs `let`.

┄┄┄┄┄┄┄┄

1. 不需要。测试就是一段调用你函数的代码。这条先执行 `count = 0;`，再依次调用 `cardCounter(2)` 到 `cardCounter(5)`，最后检查 `cardCounter(6)` 是否返回 `"5 Bet"`。
2. `count` 是全局变量，每次调用改的都是同一个 `count`，变化会累加：五张小牌，`+1` 五次，得到 `5`。
3. 写 `count = 0;` 把它归零，不然下一组会接着上一组的总数往下算。`count` 要被赋新值（在函数外面归零，在函数里面 `+1` 或 `-1`），而用 `const` 声明的变量不能赋新值，所以要用 `let`。

标签：`js::functions js::scope`
