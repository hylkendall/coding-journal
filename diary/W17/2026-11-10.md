**卡 1**

正面：
```javascript
function addPrint(a, b) {
  console.log(a + b);
}

console.log(addPrint(1, 2) + 1);
```
1. How many lines does this print? What are they, in order?
2. Why is the last line `NaN` and not `undefined1`?

┄┄┄┄┄┄┄┄

1. 这段代码一共打印几行？按顺序分别是什么？
2. 为什么最后一行是 `NaN`，而不是 `undefined1`？

背面：
1. Two lines: `3`, then `NaN`. Before the outer `console.log` can print, JavaScript must work out the value inside its parentheses, so it calls `addPrint(1, 2)`, and the function body prints `3`. The function has no `return`, so it returns `undefined`, and the outer line calculates `undefined + 1`.
2. `+` joins text only when at least one side is a string. `undefined` is not a string, so `+` does math and first converts `undefined` to a number, which gives `NaN`; `NaN + 1` is still `NaN`. Compare: `null` converts to `0`, so `null + 1` is `1`.

┄┄┄┄┄┄┄┄

1. 两行：先 `3`，再 `NaN`。外层 `console.log` 打印之前，JavaScript 得先算出它括号里的值，所以会调用 `addPrint(1, 2)`，函数体打印出 `3`。函数没写 `return`，交出 `undefined`，外层这一行算的就是 `undefined + 1`。
2. `+` 只有在至少一边是字符串时才拼接文字。`undefined` 不是字符串，所以 `+` 做数学运算，先把 `undefined` 转成数字，得到 `NaN`；`NaN + 1` 仍然是 `NaN`。对比：`null` 转成数字是 `0`，所以 `null + 1` 是 `1`。

let pet = "cat";

function check(age) {

2. What happens, and why:

3. `pet` is declared with `let` twice. Why is there no `SyntaxError: Identifier 'pet' has already been declared`?

┄┄┄┄┄┄┄┄

1. `check(20)` 和最后一行分别打印什么？
2. 下面两种情况会发生什么？为什么？
   a. 在 `check` 里面、紧跟 `if` 块的 `}` 之后，加一行 `console.log(msg);`
   b. 在文件最末尾加一行 `console.log(age);`
3. `pet` 用 `let` 声明了两次，为什么没有报 `SyntaxError: Identifier 'pet' has already been declared`？

背面：
1. `dog adult`, then `cat`.
2. a. `ReferenceError: msg is not defined`. `msg` is declared with `const` inside the `if` block's `{}`, so it exists only inside those braces (block scope).
   b. `ReferenceError: age is not defined`. A parameter is a local variable of its function, so `age` exists only inside `check` (local scope).
   Rule for both: code inside can see variables outside; code outside cannot see variables inside.
3. The two `pet`s are in different layers: one at the top level, one inside `check`. JavaScript looks in the current layer first, then moves outward, and uses the first `pet` it finds. The error only happens when the same name is declared twice in the same layer.

┄┄┄┄┄┄┄┄

2. a. `ReferenceError: msg is not defined`。`msg` 是在 `if` 块的 `{}` 里用 `const` 声明的，只在这对花括号里存在（块级作用域）。
   b. `ReferenceError: age is not defined`。形参是函数的局部变量，所以 `age` 只在 `check` 里存在（局部作用域）。
   两种情况的规则相同：里面能看外面，外面看不见里面。
3. 两个 `pet` 在不同的层：一个在最外层，一个在 `check` 里。JavaScript 先在当前这层找，找不到再往外一层找，用的是最先找到的那个 `pet`。只有在同一层里把同一个名字声明两次，才会报这个错。

**卡 3**

正面：
With `const x = true;`:
1. How do you check whether `x` is a boolean? What does `typeof true` return, and what type is that result?
2. Why do `x.typeOf` and `typeOf x` both fail?
3. What is the difference between `typeof x` and `price.toFixed(2)`? Why can't `typeof` be a method?

┄┄┄┄┄┄┄┄

已知 `const x = true;`：
1. 怎样判断 `x` 是不是布尔值？`typeof true` 返回什么？这个结果是什么类型？
2. 为什么 `x.typeOf` 和 `typeOf x` 都不行？
3. `typeof x` 和 `price.toFixed(2)` 有什么区别？为什么 `typeof` 不能是方法？

背面：
1. `typeof x === "boolean"`. `typeof true` returns `"boolean"`, which is a string, so compare it with `"boolean"` in quotes. Without quotes, `boolean` is read as a variable name, which throws `ReferenceError: boolean is not defined`.
2. `typeof` must be all lowercase and written before the value, with a space and no dot. `x.typeOf` looks for a property called `typeOf` on `x`, finds none, and gives `undefined`. JavaScript doesn't recognize `typeOf x`, so it is a `SyntaxError` and the file doesn't run.
3. `typeof` is an operator, like `!` or `-`: it does something to a value. `toFixed()` is a method: a function attached to a value, called with a dot and `()`. Memory aid: with a dot, the value does it itself; without a dot, something is done to the value. `typeof` has to work on every value, including `undefined`, which has nothing attached to it, so it can't be a method.

┄┄┄┄┄┄┄┄

1. `typeof x === "boolean"`。`typeof true` 返回 `"boolean"`，这是一个字符串，所以要和带引号的 `"boolean"` 比较。不加引号的话，`boolean` 会被当成变量名，报 `ReferenceError: boolean is not defined`。
2. `typeof` 必须全小写，写在值的前面，中间空一格，不加点。`x.typeOf` 是去 `x` 身上找一个叫 `typeOf` 的属性，找不到，得到 `undefined`。JavaScript 不认识 `typeOf x` 这种写法，所以是 `SyntaxError`，整个文件都不运行。
3. `typeof` 是运算符，和 `!`、`-` 一样，是对一个值做动作。`toFixed()` 是方法，也就是挂在值身上的函数，用"点 + `()`"来调用。记法：带点的是"让它自己做"，不带点的是"对它做"。`typeof` 必须能问任何值，包括身上什么都没有的 `undefined`，所以它不能是方法。

标签：`js::operators`

**卡 5**

正面：
```javascript
function maskEmail(email) {
  const atIndex = email.indexOf("@");
  return email.slice(0, 1) + "*".repeat(atIndex - 2) + email.slice(atIndex - 1, atIndex) + email.slice(atIndex);
}

const email = "apple.pie@example.com";
console.log(maskEmail(email));
```
1. Rule: when do you declare a variable with `const`, and when with `let`?
2. Can the parameter be written as `function maskEmail(const email)`? What kind of variable is a parameter?

┄┄┄┄┄┄┄┄

1. 规则：什么时候用 `const` 声明变量，什么时候用 `let`？
2. 形参能不能写成 `function maskEmail(const email)`？形参是一种什么样的变量？

背面：
1. Use `const` by default. Use `let` only when you know the variable will be given a new value later. Here `email` and `atIndex` are each assigned once, so both use `const`.
2. No. `function f(const x) {}` throws `SyntaxError: Unexpected token 'const'`, because writing a name inside the parentheses already declares it. A parameter is a local variable of the function: each call fills it with the argument, and, like a variable declared with `let`, it can be given a new value inside the function.

┄┄┄┄┄┄┄┄

1. 默认用 `const`。只有确定这个变量后面要被赋新值时，才用 `let`。这里的 `email` 和 `atIndex` 都只赋值一次，所以都用 `const`。
2. 不能。`function f(const x) {}` 会报 `SyntaxError: Unexpected token 'const'`，因为在括号里写下名字就已经声明了它。形参是函数的局部变量：每次调用时自动装进实参，而且和用 `let` 声明的变量一样，在函数里可以被赋新值。
