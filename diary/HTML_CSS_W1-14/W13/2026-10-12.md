**卡 1**
正面：
What is the difference between the combinators `A + B` and `A ~ B`?
组合器 `A + B` 和 `A ~ B` 有什么区别？
背面：
Both select only `B` elements that come after `A` and share `A`'s parent. `A + B` selects a `B` only if it is the element immediately after `A`; if any element sits in between, nothing is selected. `A ~ B` selects every `B` after `A`, no matter what is in between.
两者都只选中排在 `A` 后面、和 `A` 同一个父元素的 `B`。`A + B` 只在紧挨着 `A` 的下一个元素正好是 `B` 时才选中它，中间隔了任何元素就选不中。`A ~ B` 选中 `A` 后面所有的 `B`，中间隔着什么都不影响。
标签：`css::selectors`

**卡 2**
正面：
An `<a>` has no `href` attribute. Which of `:link`, `:visited`, `:any-link`, `:hover` can match it?
一个 `<a>` 没有 `href` 属性。`:link`、`:visited`、`:any-link`、`:hover` 中，哪些能选中它？
背面：
Only `:hover`. The other three match only links, and an `<a>` without `href` is not a link. `:hover` works on any element.
只有 `:hover`。另外三个只匹配链接，而没有 `href` 的 `<a>` 不算链接。`:hover` 对任何元素都有效。
标签：`css::pseudo`

**卡 3**
正面：
In what order should the `a:link`, `a:visited`, `a:hover` and `a:active` rules be written, and why?
`a:link`、`a:visited`、`a:hover`、`a:active` 这四条规则应该按什么顺序写？为什么？
背面：
`:link` → `:visited` → `:hover` → `:active` (mnemonic: LoVe HAte). All four have the same specificity, so the rule written later wins. `:hover` must come after `:link` and `:visited` to override them; `:active` comes last so it overrides `:hover` while the link is being pressed.
`:link` → `:visited` → `:hover` → `:active`（记法：LoVe HAte）。四条特异性相同，写在后面的赢。`:hover` 要排在 `:link` 和 `:visited` 后面才能盖过它们；`:active` 排在最后，按住链接的那一刻才能盖过 `:hover`。
标签：`css::pseudo` `css::specificity`

**卡 4**
正面：
Which HTML attribute or check does each of these input pseudo-class pairs depend on: `:enabled`/`:disabled`, `:required`/`:optional`, `:in-range`/`:out-of-range`, `:valid`/`:invalid`?
下面每一对输入伪类各取决于哪个 HTML 属性或哪项检查：`:enabled`/`:disabled`、`:required`/`:optional`、`:in-range`/`:out-of-range`、`:valid`/`:invalid`？
背面：
`:enabled`/`:disabled` → the `disabled` attribute
`:required`/`:optional` → the `required` attribute
`:in-range`/`:out-of-range` → `min` / `max`
`:valid`/`:invalid` → all constraints combined (`required`, `type`, `min`/`max`, etc.), so an out-of-range value also matches `:invalid`
`:enabled`/`:disabled` → `disabled` 属性
`:required`/`:optional` → `required` 属性
`:in-range`/`:out-of-range` → `min` / `max`
`:valid`/`:invalid` → 所有约束的总账（`required`、`type`、`min`/`max` 等），所以超出范围的值也会匹配 `:invalid`
标签：`css::pseudo` `html::forms`

**卡 5**
正面：
An `<input type="email">` without `required` is left empty. Does it match `:valid` or `:invalid`?
一个没写 `required` 的 `<input type="email">` 空着没填，它匹配 `:valid` 还是 `:invalid`？
背面：
`:valid`. An empty field fails validation only when it is `required`; the email format is checked only once something has been typed.
`:valid`。只有写了 `required`，空着才算不合格；邮箱格式要等输入了内容才检查。
标签：`css::pseudo` `html::forms`

**卡 6**
正面：
Which of these match `:empty`? (a) `<div></div>` (b) `<div> </div>` (one space inside) (c) `<div><!-- note --></div>`
下面哪些匹配 `:empty`？(a) `<div></div>` (b) `<div> </div>`（里面一个空格） (c) `<div><!-- 注释 --></div>`
背面：
(a) and (c). Comments don't count as content; whitespace does (as current browsers implement it).
(a) 和 (c)。注释不算内容，空格算内容（以目前浏览器的实现为准）。
标签：`css::pseudo`

**卡 7**
正面：
Why does `li::marker { background: yellow; }` have no effect, and how do you make a fully custom list bullet instead?
为什么 `li::marker { background: yellow; }` 不生效？想要完全自定义的列表符号，该怎么做？
背面：
`::marker` accepts only a small set of properties (e.g. `color`, `font-*`), and `background` is not one of them. For a fully custom bullet, remove the default with `list-style: none` and draw your own with `li::before`.
`::marker` 只接受少数属性（如 `color`、`font-*`），`background` 不在其中。要完全自定义，先用 `list-style: none` 去掉默认符号，再用 `li::before` 自己画一个。
标签：`css::pseudo`

**卡 8**
正面：
`:is()` and `:where()` are written the same way. How does each one count toward specificity?
`:is()` 和 `:where()` 写法一样。它们各自怎么计算特异性？
背面：
`:is()` takes the specificity of its most specific argument: `:is(#a, .b)` counts as an id, even when the element was matched via `.b`. `:where()` always counts as 0.
`:is()` 取括号里特异性最高的那一项：`:is(#a, .b)` 按 id 算，即使元素实际是靠 `.b` 匹配上的。`:where()` 永远算 0。
标签：`css::pseudo` `css::specificity`

**卡 9**
正面：
What does `.card:has(img)` select, and how is it different from `.card:has(> img)`?
`.card:has(img)` 选中什么？和 `.card:has(> img)` 有什么区别？
背面：
It selects the `.card` itself (not the `img`) when an `img` is anywhere inside it, at any depth. `.card:has(> img)` only counts an `img` that is a direct child.
选中的是 `.card` 本身（不是 `img`），条件是它里面任何一层有 `img`。`.card:has(> img)` 只认作为直接子元素的 `img`。
标签：`css::pseudo`

**卡 10**
正面：
A `<span>` (default `display: inline`) has `width: 100px; padding: 0 10px; border: 3px solid;`. Which of these declarations affect its rendered width?
一个 `<span>`（默认 `display: inline`）写了 `width: 100px; padding: 0 10px; border: 3px solid;`。哪几条声明会影响它渲染出来的宽度？
背面：
`padding` and `border` do: an inline element's left/right padding and borders still take up space. `width` is ignored. Rendered width = text width + 20px + 6px.
`padding` 和 `border` 会：行内元素左右的 padding 和 border 照样占位。`width` 被忽略。渲染宽度 = 文字宽 + 20px + 6px。
标签：`css::box-model`
