**卡 1**

正面：
Write a media query that applies only when the user has turned on the system's "reduce motion" setting, and stop `.logo`'s animation inside it.
写一个媒体查询，只在用户打开了系统的"减弱动态效果"设置时生效，并在里面停掉 `.logo` 的动画。

背面：
`@media (prefers-reduced-motion: reduce) { .logo { animation: none; } }`
The media feature is `prefers-reduced-motion`. The value `reduce` means the setting is on; the other value, `no-preference`, means it is off.
媒体特性是 `prefers-reduced-motion`。值为 `reduce` 表示设置已打开；另一个值 `no-preference` 表示没打开。

标签：`CSS::Accessibility`

**卡 2**

正面：
`.contact a:hover { transform: translateY(0.5rem); }`
`transition: transform 1s;` is written on the parent `.contact`, not on the `a`. Is the link's movement animated? Why?
`.contact a:hover { transform: translateY(0.5rem); }`
`transition: transform 1s;` 写在父元素 `.contact` 上，而不是写在 `a` 上。链接移动时会有过渡吗？为什么？

背面：
No. The link jumps instantly. `transition` only animates changes to properties of the element it is declared on, and it is not inherited by children. The `transform` that changes belongs to the `a`, so the `transition` must be on the `a`.
不会，链接会瞬间跳过去。`transition` 只对声明它的那个元素自身的属性变化起作用，也不会被子元素继承。发生变化的 `transform` 属于 `a`，所以 `transition` 必须写在 `a` 上。

标签：`CSS::Transition`

**卡 3**

正面：
`.contact a:hover { transform: translateY(0.5rem); }`, with `transition: transform 1s;` on the `a`. When the cursor rests near the link's top edge, the link keeps jittering up and down. Why? How do you fix it?
`.contact a:hover { transform: translateY(0.5rem); }`，`a` 上写了 `transition: transform 1s;`。鼠标停在链接上沿附近时，链接会上下抖个不停。为什么？怎么修？

背面：
The element that detects `:hover` is the same element that moves. It moves out from under the cursor, `:hover` ends, it moves back, touches the cursor again, and the cycle repeats.
Fix: wrap each link in an element that does not move (e.g. `<div class="contact-item">`), let that wrapper detect hover, and move only the link: `.contact-item:hover a { transform: translateY(0.5rem); }`. The wrapper stays put, so as long as the cursor is inside it, `:hover` is never lost. (The `a` also needs `display: inline-block`; see the transform/inline card.)
负责检测 `:hover` 的元素，就是那个在移动的元素。它移出鼠标所在的位置后 `:hover` 失效，于是退回原位，又碰到鼠标，如此循环。
解法：给每个链接套一个不会移动的外层（如 `<div class="contact-item">`），由外层检测 hover，只移动里面的链接：`.contact-item:hover a { transform: translateY(0.5rem); }`。外层不动，鼠标只要还在它的范围里，`:hover` 就不会断。（此时 `a` 还需要设 `display: inline-block`，见"transform 与行内元素"那张卡。）

标签：`CSS::Transform`

**卡 4**

正面：
A plain `<a>` (default `display: inline`) inside a `<div>` is given `transform: translateY(0.5rem)`, but it does not move. Why? And why did the same `transform` work when this `<a>` was a direct child of a `display: flex` container?
一个普通的 `<a>`（默认 `display: inline`）放在 `<div>` 里，设了 `transform: translateY(0.5rem)`，却没有移动。为什么？同样的 `transform`，在这个 `<a>` 作为 `display: flex` 容器的直接子元素时，为什么能生效？

背面：
`transform` does not apply to non-replaced inline elements, i.e. ordinary inline elements such as `<a>` and `<span>`. Replaced elements such as `<img>` are not affected by this rule. Fix: `display: inline-block` (or `block`). A direct child of a flex container is a flex item, and flex items are automatically treated as block-level, so `transform` worked there.
`transform` 对非替换行内元素不起作用，也就是 `<a>`、`<span>` 这类普通行内元素。`<img>` 这类替换元素不受这条规则影响。解法：设成 `display: inline-block`（或 `block`）。flex 容器的直接子元素是 flex 项目，会被自动当成块级元素处理，所以那时 `transform` 能生效。

标签：`CSS::Transform`

**卡 5**

正面：
`#navbar li { padding: 1rem; }`
`#navbar li:hover { background-color: ...; }`
The `a` inside each `li` keeps its default `display: inline`. What usability bug does this cause, and how do you fix it?
`#navbar li { padding: 1rem; }`
`#navbar li:hover { background-color: ...; }`
每个 `li` 里的 `a` 保持默认的 `display: inline`。这会造成什么可用性 bug？怎么修？

背面：
The highlight covers the whole `li` (including its padding), but only the `a`'s text is clickable. Clicking the highlighted edge does nothing.
Fix: move the padding onto the `a`, give the `a` `display: block`, and put `:hover` on the `a`. Then the highlighted area and the clickable area are the same box.
高亮覆盖整个 `li`（含 padding），但能点的只有 `a` 的文字部分，点高亮区域的边缘没反应。
解法：把 padding 移到 `a` 上，给 `a` 设 `display: block`，`:hover` 也写在 `a` 上。这样高亮区域和点击区域就是同一个盒子。

标签：`CSS::BoxModel`

**卡 6**

正面：
`#navbar { position: fixed; }` has no `top` set, yet it sits at the top of the viewport. Why does this work, and why should you still write `top: 0`?
`#navbar { position: fixed; }` 没有写 `top`，却贴在视口顶部。为什么这样也行？为什么仍然应该写 `top: 0`？

背面：
When an `absolute` or `fixed` element has no vertical offset (`top` and `bottom` both `auto`), it stays vertically at its static position, i.e. where it would sit in normal flow. The same applies horizontally with `left`/`right`. The navbar is the first element in `<body>` and body's margin is reset to 0, so that position happens to be the top. Add anything before it and it is no longer at the top. `top: 0` pins it explicitly.
`absolute` 或 `fixed` 元素没有垂直方向的偏移量（`top` 和 `bottom` 都是 `auto`）时，它在垂直方向上会停在静态位置，也就是它在正常文档流里本来的位置。水平方向上的 `left`/`right` 同理。导航栏是 `<body>` 里的第一个元素，body 的 margin 又被重置成了 0，所以这个位置碰巧就是顶部。在它前面加任何元素，它就不在顶部了。写上 `top: 0` 才是明确地把它固定在顶部。

标签：`CSS::Positioning`
