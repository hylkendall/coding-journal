**卡 1**

正面
```
What do tabindex="0", tabindex="-1", and a positive tabindex (e.g. tabindex="3") each do? Which kind should you never use?
- - - - - - - - - -
tabindex="0"、tabindex="-1"、正数 tabindex（比如 tabindex="3"）分别起什么作用？哪一种永远不该用？
```

背面
```
0: the element joins the Tab order at its position in the HTML source order.
-1: the Tab key never reaches it, but it can still receive focus from script (e.g. JS calling focus()).
Positive: it moves ahead of every focusable element that has tabindex="0" or no tabindex. Never use positive values: the Tab order stops matching the order users see on screen.
- - - - - - - - - -
0：按它在 HTML 书写顺序中的位置加入 Tab 顺序。
-1：按 Tab 永远到不了它，但程序（比如 JS 调用 focus()）仍然可以把焦点送过去。
正数：排到所有 tabindex="0" 或没写 tabindex 的可获得焦点元素前面。永远不要用正数：Tab 顺序会和用户在屏幕上看到的顺序对不上。
```

标签
```
html::accessibility
```

**卡 2**

正面
```
A page has elements with positive tabindex values, elements with tabindex="0", and natively focusable elements. In what order does the Tab key move focus through them?
- - - - - - - - - -
页面上同时有 tabindex 为正数的元素、tabindex="0" 的元素，以及天生能获得焦点的元素。按 Tab 时，焦点按什么顺序经过它们？
```

背面
```
Two tiers:
1. Elements with a positive tabindex, in ascending order (1, 2, 3...).
2. Then every other focusable element (tabindex="0" and natively focusable elements such as button, input, and a with href), in HTML source order.
tabindex="0" is not "the smallest number": it belongs to tier 2. Elements with tabindex="-1" are skipped.
- - - - - - - - - -
分两档：
1. 先走 tabindex 为正数的元素，按数字从小到大（1、2、3……）。
2. 再走其余能获得焦点的元素（tabindex="0" 的元素，以及 button、input、带 href 的 a 这类天生能获得焦点的元素），按 HTML 书写顺序。
tabindex="0" 不是「最小的数字」，它属于第 2 档。tabindex="-1" 的元素会被跳过。
```

标签
```
html::accessibility
```

**卡 3**

正面
```
What is the difference between aria-label and aria-labelledby? When should you use aria-label?
- - - - - - - - - -
aria-label 和 aria-labelledby 有什么区别？什么情况下用 aria-label？
```

背面
```
Both give an element its accessible name (the name assistive technologies read out).
aria-label: you write the name directly as the attribute's value.
aria-labelledby: the value is the id of another element, and that element's existing text on the page becomes the name.
Use aria-label when there is no visible text on the page to reference, e.g. an icon-only button.
- - - - - - - - - -
两者都是给元素一个无障碍名称（辅助技术读出来的名字）。
aria-label：名字直接写在属性值里。
aria-labelledby：属性值是另一个元素的 id，借那个元素在页面上现成的文字当名字。
页面上没有现成的文字可借时用 aria-label，比如只有图标的按钮。
```

标签
```
html::accessibility
```


背面
```
It reads that text as a description (extra information read after the input's name), not as the name itself.
Nothing changes on screen: the pw-help text is displayed exactly as before.
- - - - - - - - - -
把那段文字当作补充说明，在输入框的名字之后读出，而不是当成名字。
屏幕上没有任何变化：pw-help 的文字原来怎么显示，现在还怎么显示。
```

正面
```
Do the ARIA attributes aria-label, aria-labelledby, aria-describedby, and aria-hidden change what sighted users see on screen? Explain with aria-hidden="true" on a decorative icon.
- - - - - - - - - -
aria-label、aria-labelledby、aria-describedby、aria-hidden 这几个 ARIA 属性，会改变视力正常的用户在屏幕上看到的东西吗？用装饰性图标加 aria-hidden="true" 来说明。
```

```
No. These attributes only change what assistive technologies read.
A decorative icon with aria-hidden="true" is still displayed on screen, but screen readers skip it.
- - - - - - - - - -
不会。这几个属性只改变辅助技术读到的内容。
装饰性图标加了 aria-hidden="true"，屏幕上照常显示，屏幕阅读器跳过不读。
```

```
A time element shows "9 a.m. on October 24, 2026". Write its datetime attribute in ISO 8601 format. What rule about the hour is easy to get wrong?
- - - - - - - - - -

```

背面
```
datetime="2026-10-24T09:00"
The hour must have two digits (09, not 9). A capital T separates the date and the time. Seconds are optional.
- - - - - - - - - -
datetime="2026-10-24T09:00"
小时必须写两位（09，不是 9）。大写 T 分隔日期和时间。秒可以省略。
```
